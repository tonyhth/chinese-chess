## P0 复核

### 4-P0-1. `feature.gameRecordImport` key 缺失 ✅ 确认

验证：`UnlockedFeature.swift:77` 确实引用 `L10n.shared.t("feature.gameRecordImport")`，xcstrings 中只有 `feature.gameRecordExport`，import 版本不存在。**P0 成立。**

### 4-P0-2. macOS CommandMenu 硬编码 ✅ 确认

验证：`ChineseChessApp.swift:542` `CommandMenu("引擎")`，`:547` `Button("配置引擎")`，而 `:520` 的另一个 CommandMenu 正确使用了 `L10n.shared.t("game.menuLabel")`。说明同一个文件中存在不一致——前一个做了 i18n，后一个遗漏了。`engine.menuTitle` 和 `engine.configure` key 在 xcstrings 中也不存在，需要新增。**P0 成立。**

### 4-P0-3. 棋盘"楚河汉界"硬编码 ✅ 确认，但需补充重要发现

验证：6 处硬编码确认存在。但**关键补充**——xcstrings 中 `board.chuRiver` 和 `board.hanBorder` 的英文翻译也是中文：

```json
"board.chuRiver": en → "楚  河"
"board.hanBorder": en → "汉  界"
```

**这是 intentional 的文化设计**，不是遗漏。楚河汉界是中国象棋的文化固有元素，类似围棋的 "Komi" 不翻译。即使修复为引用 xcstrings key，英文用户看到的仍是中文。

**建议：** 仍然应该改为引用 xcstrings key（消除硬编码 code smell），但这是 **P1 而非 P0**——因为最终视觉效果不变，英文用户看到的仍然是"楚河汉界"，这是正确的文化呈现。

## P1 复核

### 4-P1-1. BoardTheme 硬编码 ✅ 确认

验证：`BoardTheme.swift:17-19` 三个主题名硬编码，`:36-39` 四条解锁条件硬编码。`classicWood` 和 `inkStone` 正确走了 L10n，其余三个遗漏。模式不一致，**P1 成立。**

### 4-P1-2. PGN 硬编码 ✅ 确认，同意降级建议

验证：PGNExporter `[Site "中国象棋"]` 和来源标签（人机对弈/残局练习/导入棋谱）确实硬编码。

**复核意见：** 
- `[Site "中国象棋"]`：PGN 标准元数据，保持中文是合理的——PGN 是机器可读格式，Site 字段不影响 UI。**不建议国际化，降为 P2。**
- PGNImporter 错误信息（"第 X 步非法走法"等）会通过 `error.localizedDescription` 冒泡到 UI，**这些应该国际化，维持 P1。**
- 来源标签（人机对弈/残局练习/导入棋谱）：这些会写入 PGN 的 `[Event]` 标签，也是机器可读格式，**降为 P2。**

### 4-P1-3. SettingsView "中文" 硬编码 ✅ 确认，同意 Vera 判断

验证：`Text("中文").tag("zh-Hans")` 和 `Text("English").tag("en")` 并列。语言名称用本语种显示是行业惯例（Windows/macOS/iOS 都这样），**这是正确的 intentional 设计**。建议加注释说明即可。**降为 P2。**

### 4-P1-4. AIEngine displayName 硬编码 ✅ 确认

验证：`AIEngine.swift:628` `var displayName: String { "内置引擎" }`，xcstrings 中 `engine.builtIn` 英文翻译为 "Built-in"。**P1 成立，改一行即可。**

### 4-P1-5. CLI 工具全中文 ✅ 确认

验证：SelfPlayRunner/CMAESOptimizer/OpeningBookExpander 的 print 输出确实全中文。同意 Vera 的降级说明——这些是开发者 CLI 工具，不面向终端用户。**统一降为 P2。**

### 4-P1-6. 未引用 key 统计 ✅ 确认，数量修正

我独立跑了静态分析：
- 总 key：541
- 静态引用：352
- 未引用：189（Vera 报 174，差异来自动态构造模式识别口径不同）
- 其中动态构造合法引用：36（daily.type.*/daily.streak.day*）
- **真正未使用：153 个**

主要分布：achievement.*（93 个）、chapter.*（14 个）、notation.*（7 个）。achievement 的 93 个未引用 key 是因为成就系统定义了完整的 name/desc 但 UI 尚未完全接入。**维持 P1，建议标记为预留 key 或清理。**
