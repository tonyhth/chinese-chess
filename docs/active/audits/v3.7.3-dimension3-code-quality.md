## 2. 重复代码

### P1-1: boardFingerprint() 重复实现

- **文件：** `ViewModels/GameViewModel.swift:575` 与 `ViewModels/PuzzleViewModel.swift:520`
- **级别：** P1
- **问题：** 两个 ViewModel 各自实现了 `boardFingerprint()`，但逻辑不同：
  - GameViewModel: 使用 `FENParser.generate(board: board)` —— 标准 FEN 表示
  - PuzzleViewModel: 手动拼接 `"row+col+kind+side"` 字符串 —— 自定义格式
  - 两者实现不同但功能相似（生成棋盘唯一标识），存在维护风险：如果一方修改了棋盘表示方式，另一方不会同步
- **建议：** 统一为 `Board` 扩展方法 `var fingerprint: String`，提供标准实现。如果 PuzzleViewModel 需要更轻量的表示，可以在 Board 扩展中提供 `var lightweightFingerprint: String` 并注释说明差异原因

## 4. 魔法数字与硬编码值

### P1-6: 棋盘尺寸硬编码（无统一常量）

- **文件：** `Models/MoveValidator.swift:64,79` / `Models/Board.swift:46-54` / `Models/GameMove.swift:35,37`
- **级别：** P1
- **问题：** 棋盘尺寸 `9`（列数）、`10`（行数）、`8`（最大列索引）散布在多个文件中，以裸数字形式出现。MoveValidator 中 `r <= 9 && c <= 8` 是边界检查，Board 中 `Position(row: 9, col: 0)` 是初始布局。没有统一的 `BoardConstants` 定义
- **建议：** 新增 `Board` 常量：
  ```swift
  extension Board {
      static let rowCount = 10
      static let colCount = 9
      static let maxRowIndex = 9
      static let maxColIndex = 8
  }
  ```
  全局替换裸数字

### P2-3: Task.sleep 硬编码纳秒常量

- **文件及行号：**
  - `ViewModels/PuzzleViewModel.swift:322` — `300_000_000` (0.3s)
  - `ViewModels/PuzzleViewModel.swift:399` — `800_000_000` (0.8s)
  - `Views/ChessBoardView.swift:379` — `500_000_000` (0.5s)
  - `Views/PuzzleSelectView.swift:68` — `300_000_000` (0.3s)
- **级别：** P2
- **问题：** 延迟时间以纳秒裸数字硬编码，含义不直观
- **建议：** 统一使用 `.seconds(0.3)` / `.milliseconds(300)` 风格（iOS 16+/macOS 13+ 支持 `Duration`）

### P2-4: Thread.sleep(forTimeInterval: 0.5)

- **文件：** `AI/EmbeddedPikafishEngine.swift:144`
- **级别：** P2
- **问题：** 使用 `Thread.sleep` 阻塞当前线程，在异步上下文中不合适
- **建议：** 改为 `try? await Task.sleep(for: .seconds(0.5))`

## 7. 命名一致性

### P2-7: iOSCapturedPiecesSection 方法命名

- **文件：** `Views/StatusBarView.swift:132`
- **级别：** P2
- **问题：** 方法名 `iOSCapturedPiecesSection()` 以小写 `i` 开头加大写 `OS`，不符合 Swift API Design Guidelines 的首字母大写规则（应为 `iosCapturedPiecesSection` 或更好的 `mobileCapturedPiecesSection`）
- **建议：** 重命名为 `mobileCapturedPiecesSection()` 或 `compactCapturedPiecesSection()`

### P2-8: 协议命名不一致

- **文件：** `AI/AIEngineProtocol.swift:5` vs `AI/EngineProtocol.swift:7`
- **级别：** P2
- **问题：** 两个协议文件命名风格不一致：`AIEngineProtocol` 带 `Protocol` 后缀，`ChessEngine` 不带。Swift API Guidelines 推荐不带后缀
- **建议：** `AIEngineProtocol` → `AIEngine`（如果命名冲突则用 namespace 区分）

### P2-9: L10n 单例调用风格

- **文件：** 全项目 `L10n.shared.t("key")` 出现 ~100+ 处
- **级别：** P2
- **问题：** `L10n.shared.t("key")` 调用冗长。Swift API Design Guidelines 建议方法名应包含动词，`t` 过于简短
- **建议：** 可提供更简洁的调用方式如 `L10n.string("key")` 或 `l10n("key")`。当前可用但不够优雅
