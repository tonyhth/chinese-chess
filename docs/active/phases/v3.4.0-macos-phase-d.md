## 用户感知功能变化清单

> **P2-11**:明确 v3.4.0 相比 v3.3.x 的功能变化。

### 功能新增

| 功能 | 说明 |
|------|------|
| ✅ macOS 嵌入引擎 | 开箱即用,无需下载配置 pikafish |
| ✅ iOS/macOS 架构统一 | 一套引擎集成层,双平台共用 |

### 功能退化(已知)

| 功能 | v3.3.x | v3.4.0 | 恢复计划 |
|------|--------|--------|----------|
| ❌ 实时搜索信息 | 外部进程方案通过 UCI stdout 输出 depth/score/nps/pv | 嵌入方案无 info callback,UI 仅显示"思考中..." | v3.4.1/v3.5.0 |
| ❌ UCI 调试输出 | stdout 可供高级用户排查问题 | 无 UCI 输出(C API 不暴露) | 可通过日志文件间接获取(pikafish 输出到 stderr) |
| ❌ 自定义外部引擎 | 可配置任意 UCI 引擎 | 仅支持内置 Pikafish | 不恢复(架构简化决策) |

### 发布决策

功能退化可接受:
- info callback 承诺 v3.4.1/v3.5.0 补上,间隔可控(< 1 个月)
- UCI 调试能力仅影响极少数高级用户,可通过 stderr 日志间接获取
- 自定义外部引擎是高级功能,主流用户不使用

## NNUE 嵌入验证详解

> NNUE 权重文件（~48MB）作为 Bundle Resource 运行时加载，不编译进 `.a` 静态库。
> 这两项测试验证运行时加载路径的正确性。

### 测试 #15: NNUE 运行时加载

**前置条件**: App 正常打包，`PikafishEngine.bundle` 内包含 NNUE 文件

**操作步骤**:
1. 启动 App（终端启动以便查看 stderr）:
   ```bash
   open ~/DevTeam/projects/chinese-chess/中国象棋-v3.4.0.app --stdout --stderr
   # 或从 Xcode 直接 Run
   ```
2. 进入设置，开启嵌入引擎
3. 检查 stderr / Console 输出

**预期输出**:
```
[PikafishAPI] NNUE file EXISTS at expected path: .../PikafishEngine.bundle/Contents/Resources/pikafish.nnue
[PikafishAPI] pikafish_init() succeeded, version: ...
```

**通过标准**: NNUE 文件存在 + init 成功 + version 正确

### 测试 #16: NNUE 缺失 fallback

**操作步骤**:
1. 找到 App 包内 NNUE 文件:
   ```bash
   NNUE_PATH=$(find ~/DevTeam/projects/chinese-chess/中国象棋-v3.4.0.app -name "*.nnue" | head -1)
   echo $NNUE_PATH
   ```
2. 移除（或重命名）NNUE 文件:
   ```bash
   mv "$NNUE_PATH" "${NNUE_PATH}.bak"
   ```
3. 启动 App
4. 开启嵌入引擎

**预期行为**:
- stderr 输出: `[PikafishAPI] NNUE file NOT FOUND at expected path`
- `pikafish_init()` 返回 -1
- App 不崩溃，显示 Alert: "Pikafish 启动失败，已切换到内置引擎"
- 自动回退到内置引擎

**测试后恢复**:
```bash
mv "${NNUE_PATH}.bak" "$NNUE_PATH"
```

## 紧急回退(P2-12)

如果 v3.4.0 发布后发现严重 bug(如特定 macOS 版本崩溃),可通过编译期 feature flag 切回外部进程方案:

```swift
// 编译期开关(默认 false)
#if DEBUG_ENABLE_EXTERNAL_ENGINE_FALLBACK
// ExternalEngineManager 代码恢复编译
#endif
```

重新编译发布后,外部进程方案恢复可用。这不是运行时开关,需要重新发布 App。
