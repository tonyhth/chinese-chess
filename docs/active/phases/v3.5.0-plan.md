# v3.5.0 版本规划

> 负责人：Alex | 日期：2026-06-29
>
> 前置：v3.4.0 已交付。v3.5.0 聚焦架构重构、技术债务清理、功能补全。

---

## 一、版本目标

1. **架构健康度提升**：解决 v3.4.0 审计发现的 P1 架构问题
2. **技术债务清零**：清理全部可执行的技术债务
3. **功能补全**：补上 v3.4.0 deferred 的 info callback
4. **构建系统统一**：SPM → xcodegen，简化构建链路

### Phase 1：架构重构（P1，阻塞后续）

> 所有架构改动集中在 Phase 1，后续 Phase 依赖重构后的模块边界。

#### 1.1 AIEngine.swift 拆分 [P1]

**问题**：1357 行、39 函数、跨 5 职责（搜索核心 / 评估 / 位置表 / 将帅安全 / 动态价值）

**目标结构**：

```
AI/
├── AIEngine.swift          # 搜索核心（negamax / IDS / quiescence / 难度路由）~400行
├── AIEvaluator.swift        # 评估函数 + 动态价值表 ~300行
├── PositionTables.swift     # 位置权重表（纯数据）~250行
├── KingSafetyEvaluator.swift # 将帅安全评估 ~200行
└── AIConstants.swift        # 常量定义 ~100行
```

**拆分原则**：
- 评估逻辑（`evaluate()` + 子力价值 + 位置加分）→ AIEvaluator
- 位置权重表（红/黑各棋子的位置加分数组）→ PositionTables
- 将帅安全（`evaluateKingSafety()` + 相关辅助）→ KingSafetyEvaluator
- 搜索核心（`bestMove` + `negamax` + `quiescenceSearch` + `IDS`）→ AIEngine

**约束**：不改变搜索逻辑和评估结果，纯文件拆分。拆分后跑全部测试确认行为不变。

**接口设计**（Vera P1-3）：
- AIEngineProtocol 留在 AIEngine.swift
- AIEngine 持有 AIEvaluator 实例（依赖注入），不继承一堆 private 方法
- 当前 evaluate/kingSafetyScore 等 private 方法 → AIEvaluator 的 internal 方法
- AIEngine 调用 `evaluator.evaluate(board:difficulty:)` 而非内部方法

#### 1.2 AIEngine 改 actor [P1]

**问题**：AIEngine 是 `final class`，有可变状态（moveOrderer），通过 EngineRouter 的 `nonisolated var native` 暴露，存在并发隐患。

**方案**：改为 `actor AIEngine`，ChessEngine 协议已经是 async，天然兼容。

**init 策略**（Vera P0）：保持同步 init，开局库异步加载放到 Phase 3.1 单独处理：
```swift
actor AIEngine {
    private let openingBook: OpeningBook  // 同步 init，Phase 3.1 再改异步
    init() { openingBook = OpeningBook() }  // 编译通过
    init(weights: EvalWeights) { ... }  // CMA-ES 注入版本
}
```

**影响面（完整清单）**：
- `bestMove(for:difficulty:isIOS:)` → `async`
- `stopSearch()` / `newGame()` / `shutdown()` → `async`（ChessEngine 协议已声明 async）
- `EngineRouter.native` 访问需 await
- **PuzzleViewModel.swift:42** — `private let aiEngine = AIEngine()` → init 同步，无需改动（但 bestMove 调用需 await）
- **SelfPlayRunner.swift:75/80** — `AIEngine()` / `AIEngine(weights:)` → init 同步，无需改动（但 bestMove 调用需 await）
- **CMAESOptimizer** — 并行评估模式受益于 actor（无竞态），bestMove 调用适配 async

**依赖**：1.1 拆分完成后执行，降低单个改动复杂度。

**AIEngine 改 actor 完整影响面**：

| 文件 | 当前代码 | 改 actor 后适配 |

| EngineRouter.swift:17 | `private let nativeEngine = AIEngine()` | ✅ init 同步，无需改 |

#### 1.3 EngineType 枚举语义修正 [P1]

**问题**：`.external` 用于嵌入式 Pikafish，语义不准确。

**影响**：需检查 View 层对 `.external` 的条件判断。当前代码注释说明 StatusBarView/ToolbarView 用 `useEmbeddedEngine` 判断 UI，不依赖 engineType，改动安全。

### Phase 2：功能补全

#### 2.1 Pikafish info callback [P1]

**问题**：v3.4.0 嵌入引擎无实时搜索信息（depth/score/nps/pv），UI 仅显示"思考中..."。这是 v3.4.0 的已知退化，承诺 v3.4.1/v3.5.0 补上。

**方案**：

C API 侧（如果支持）：
- 检查 `pikafish_api.h` 是否有 info callback / search info 输出接口
- 如果有：Swift 侧注册回调，通过 actor 转发到 UI
- 如果没有：在 `pikafish_best_move` 执行期间通过 stderr 或自定义回调获取信息

Swift 侧：
- EmbeddedPikafishEngine 新增 `searchInfo` AsyncStream 或 @Observable 属性
- GameViewModel 监听 info 更新，转发到 StatusBarView
- StatusBarView 显示 depth/score/nps/pv

**风险**：C API 可能不暴露 info callback。如果不支持，评估以下替代：
- 方案 B：pikafish 支持设置 output callback（需修改 C API）
- 方案 C：放弃此功能，UI 改进为"已思考 N 秒"计时器

**前置确认**：Vera 已确认 `pikafish_api.h` 无 info callback 接口（仅 7 个函数：init/best_move/stop/new_game/quit/set_option/get_info）。`get_info()` 只返回版本字符串。

**采用方案 C**：计时器 UI（"已思考 N 秒"），不做 info callback。info callback 需修改 C++ wrapper，单独立项 v3.6.0。

**实现**：
- GameViewModel 在 bestMove 调用前记录 startTime
- StatusBarView 显示 "思考中... (Ns)"，N 每秒更新
- bestMove 返回后停止计时

### Phase 3：性能优化

#### 3.1 开局库异步加载 [P1]

**问题**：`OpeningBook()` 在 `AIEngine.init()` 中同步加载 3.7MB JSON。AIEngine 在 EngineRouter（@MainActor）初始化，即开局库在主线程同步加载。

**方案**：

```swift
actor AIEngine {
    private var openingBook: OpeningBook?

    init() async {
        // 在 actor 上下文（后台）加载
        self.openingBook = await Task.detached {
            OpeningBook()
        }.value
    }

    func bestMove(...) async -> Move? {
        guard let book = openingBook else {
            // 开局库未加载完成，直接搜索
        }
    }
}
```

**注意**：依赖 Phase 1.2（AIEngine 改 actor）。

#### 3.2 print() 清理 [P2]

**问题**：76 处 print() 在非测试代码中。

**方案**：
- 调试日志 → 删除或改为 `os_log(.debug)`
- stderr 调试 → 删除（引擎层已有 NSLog）
- 确认无敏感信息

**工期**：0.5 天

#### 3.3 TT incrementAge 死代码 [P2]

**确认**：需 grep 确认是否真是死代码。如果 `incrementAge()` 从未被调用，删除。

**工期**：0.5 小时
