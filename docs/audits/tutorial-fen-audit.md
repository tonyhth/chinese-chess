## 2. 逐课详细分析

### 课3: 走子练习

**FEN**: `3aka3/9/9/9/9/9/9/9/4K4/4R4 w - - 0 1`
**expectedMoves**: `["e0d0"]` — 红车从 e0 横移到 d0

#### 棋子分布
| 棋子 | FEN 坐标 | UCI 坐标 | 说明 |
|------|---------|---------|------|
| 黑士 ×2 | (0,3), (0,5) | d9, f9 | 黑方九宫格内 |
| 黑将 | (0,4) | e9 | 黑方底线中心 |
| 红帅 | (8,4) | e1 | 红方二路中心 |
| 红车 | (9,4) | e0 | 红方底线中心 |

#### 1) 教学目标 vs FEN 局面
- 教学目标是"学会车的横向移动"
- 红车在 e0，红帅在 e1 — 两个红方棋子紧贴在 e 线，对新手造成视觉干扰
- 黑方双士+将摆在顶部，与"走子练习"完全无关，是纯装饰
- 补帅没有挡住横移路径（帅在 row 8，车在 row 9），功能上不影响

#### 2) expectedMoves 分析
- 红车纵向上被红帅挡住（e1 有 K），只能横向走
- 但横向有 8 个合法目标 (a0~i0 除 e0)，d0 只是其中之一
- **歧义严重**：新手走 a0/b0/c0/f0 等都是合理的横移，但会被判错

#### 3) 局面自然性
- 黑方双士+将摆在底线是初始局面残留，不算突兀
- 但红车+红帅叠在 e 线底部，棋盘其余位置全空，非常不自然

#### 4) 改进建议 → 见 §3

### 课5: 将军练习 ⛔ P0 严重BUG

**FEN**: `3aka3/9/9/9/4P4/9/9/9/4K4/2C6 w - - 0 1`
**expectedMoves**: `["c0e0"]` — 红炮横移到 e0 形成将军

#### 棋子分布
| 棋子 | FEN 坐标 | UCI 坐标 | 说明 |
|------|---------|---------|------|
| 黑士 ×2 | (0,3), (0,5) | d9, f9 | |
| 黑将 | (0,4) | e9 | 被将军目标 |
| 红兵 | (4,4) | e5 | 炮架 |
| 红帅 | (8,4) | e1 | **⚠️ 补入的** |
| 红炮 | (9,2) | c0 | |

#### ⛔ 核心问题：补帅破坏了炮将军逻辑

炮将军规则：**吃子/将军时，炮和目标之间必须恰好有 1 个棋子（炮架）**

分析 e 线（col 4）从炮到将之间的棋子：
```
FEN row 0: k (黑将) ← 目标
FEN row 1: 空
FEN row 2: 空
FEN row 3: 空
FEN row 4: P (红兵) ← 炮架 ✅
FEN row 5: 空
FEN row 6: 空
FEN row 7: 空
FEN row 8: K (红帅) ← ⛔ 第二个棋子！补帅引入
FEN row 9: 空 (炮移到此处后)
```

炮在 e0 (FEN row 9) → 黑将在 e9 (FEN row 0)：
- 中间棋子：红兵(row 4) + **红帅(row 8)** = **2 个棋子**
- 炮的翻山规则要求恰好 1 个 → **将军不成立！**

**结论**：commit 16a732e 补的红帅在 e1，让 e 线多出一个棋子，直接废掉了课5的将军教学。`expectedMoves: ["c0e0"]` 变成了错误答案。

#### 修复方案
红帅必须**不在 e 线**。移到 d1 或 f1（FEN row 8 col 3 或 col 5），都在红方九宫格内。

**推荐修复 FEN**：`3aka3/9/9/9/4P4/9/9/9/3K5/2C6 w - - 0 1`
- 红帅在 d1（FEN row 8 col 3），不在 e 线
- e 线只有红兵一个炮架 → 炮将军成立 ✅
- 红帅在九宫格内（col 3, row 8）✅

### 课6: 应将练习

**FEN**: `4k4/9/9/4P4/9/9/4C4/9/9/4K4 b - - 0 1`
**expectedMoves**: `["e9d9"]` — 黑将左移躲避

#### 棋子分布
| 棋子 | FEN 坐标 | UCI 坐标 | 说明 |
|------|---------|---------|------|
| 黑将 | (0,4) | e9 | 被将军 |
| 红兵 | (3,4) | e6 | 炮架 |
| 红炮 | (6,4) | e3 | 将军方 |
| 红帅 | (9,4) | e0 | 红方底线中心 |

#### 将军验证
- 炮在 e3 (FEN row 6)，炮架红兵在 e6 (FEN row 3)，目标黑将在 e9 (FEN row 0)
- 炮到将之间：FEN row 5 空, row 4 空, row 3 红兵(炮架), row 2 空, row 1 空, row 0 黑将
- **恰好 1 个棋子（红兵）→ 将军成立 ✅**
- 红帅在 FEN row 9，在炮的另一侧，不影响 ✅

#### expectedMoves 歧义
- 黑将在 FEN(0,4)，可走方向：
  - 左移 d9 (FEN row 0 col 3)：离开 e 线，解除将军 ✅
  - 右移 f9 (FEN row 0 col 5)：离开 e 线，解除将军 ✅
  - 前进 e8 (FEN row 1 col 4)：仍在 e 线，炮通过兵架继续将军 ❌ 不可行
- **d9 和 f9 都是正确应将**，但 expectedMoves 只接受 d9
- 新手走 f9 会被判错 → 教学体验差

#### 改进方案

在 f9 放一个黑士堵住右逃路线，强制 d9 唯一：
- 原 row 0: `4k4` → 改为 `4ka3`（空4 + 将 e9 + 士 f9 + 空3 = 9位 ✅）
- 黑将可走 d9（空），f9 被黑士占 → 应将走法唯一

FEN: `4ka3/9/9/4P4/9/9/4C4/9/9/4K4 b - - 0 1`

**推荐修复 FEN**：`4ka3/9/9/4P4/9/9/4C4/9/9/4K4 b - - 0 1`
- 黑将在 e9，黑士在 f9 堵住右路
- 黑将唯一逃跑路线：d9 ✅
- 将军逻辑不变 ✅

### 课8: 避免送子

**FEN**: `4k4/4r4/9/4c4/9/4R4/9/9/4K4/9 w - - 0 1`
**expectedMoves**: `["e4d4"]` — 红车横移避战

#### 棋子分布
| 棋子 | FEN 坐标 | UCI 坐标 | 说明 |
|------|---------|---------|------|
| 黑将 | (0,4) | e9 | |
| 黑车 | (1,4) | e8 | 伏击方 |
| 黑炮 | (3,4) | e6 | 诱饵 |
| 红车 | (5,4) | e4 | 操作方 |
| 红帅 | (8,4) | e1 | |

#### ⚠️ 所有 5 个棋子 + 红帅全在 e 线（col 4）

#### 教学逻辑验证
- 红车吃炮 (e4→e6)：路径 row 4 空 ✅，可吃
- 吃完后红车在 FEN(3,4)，黑车在 FEN(1,4) 沿 e 线吃下来：路径 row 2 空 ✅
- 净亏一车 → "贪吃送子"的教学逻辑成立 ✅
- 正确走法 e4d4（横移避战）→ 合理 ✅

#### 问题 1：局面极不自然
- 6 个棋子全在 e 线一列，这在实战中不可能出现
- 对新手来说，这种局面更像"排局"而非"实战场景"
- 教学目标是"避免送子"的战术意识，应该用接近实战的局面

#### 问题 2：expectedMoves 歧义
- 红车在 e4 可选的安全走法：
  - 横移到 d4, f4, a4...（只要不吃黑炮都是"安全"的）
  - 纵向后退 e3, e2（也可安全）
- expectedMoves 只接受 d4，其他安全走法被判错
- 这是"避免类"教学的固有问题：正确答案是一个集合，不是单一走法

#### 改进建议 → 见 §3

## 3. 白脸将（飞将）违规专项分析

> 洪涛追加发现：所有 6 节课红帅和黑将都在 e 列（col 4），需逐课验证白脸将合规性。

**规则**：红帅和黑将不能在同一列且中间没有任何棋子（白脸将/飞将），否则为非法局面。

### 3.1 逐课白脸将验证

| 课 | 帅位置 | 将位置 | 同列? | 中间棋子 | 白脸将? |
|----|--------|--------|-------|----------|--------|
| 3 | FEN(8,4) e1 | FEN(0,4) e9 | ✅ 同 e 列 | **无** | ❌ **违规** |
| 4 | FEN(8,4) e1 | FEN(0,4) e9 | ✅ 同 e 列 | **无**（黑炮在 d 列不在 e 列） | ❌ **违规** |
| 5 | FEN(8,4) e1 | FEN(0,4) e9 | ✅ 同 e 列 | 红兵 FEN(4,4) | ✅ 合法 |
| 6 | FEN(9,4) e0 | FEN(0,4) e9 | ✅ 同 e 列 | 红兵 FEN(3,4) + 红炮 FEN(6,4) | ✅ 合法 |
| 7 | FEN(8,4) e1 | FEN(0,4) e9 | ✅ 同 e 列 | 黑卒 FEN(1,4) | ✅ 合法 |
| 8 | FEN(8,4) e1 | FEN(0,4) e9 | ✅ 同 e 列 | 黑车 FEN(1,4) + 黑炮 FEN(3,4) + 红车 FEN(5,4) | ✅ 合法 |

### 3.2 违规详情

**课3 白脸将违规**：红帅 e1 (FEN row 8, col 4) 与 黑将 e9 (FEN row 0, col 4) 同在 e 列，中间 FEN rows 1-7 的 col 4 全空。这是一个完全非法的象棋局面——帅将直接对面，任何象棋引擎都会拒绝此 FEN。

**课4 白脸将违规**：红帅 e1 (FEN row 8, col 4) 与 黑将 e9 (FEN row 0, col 4) 同在 e 列，中间 FEN rows 1-7 的 col 4 全空。黑炮在 d6 (FEN row 3, col 3) 不在 e 列，不构成阻隔。

### 3.3 根因

commit 16a732e 一刀切在 FEN row 8 col 4（e 列）补红帅，而黑将也在 e 列。对于课3和课4，e 列帅将之间本来就没有任何教学棋子（课3全是空行，课4黑炮在 d 列），补帅直接制造了白脸将违规。

### 3.4 修复方案验证

本文 §4 提出的修复方案（帅从 e1 移到 d1）是否同时解决白脸将问题？

| 课 | 修复后帅位置 | 修复后将位置 | 同列? | 白脸将? |
|----|-------------|-------------|-------|--------|
| 3 | d1 (FEN row 8, col 3) | e9 (FEN row 0, col 4) | ❌ 不同列 | ✅ 消除 |
| 4 | d1 (FEN row 8, col 3) | e9 (FEN row 0, col 4) | ❌ 不同列 | ✅ 消除 |
| 5 | d1 (FEN row 8, col 3) | e9 (FEN row 0, col 4) | ❌ 不同列 | ✅ 消除 |
| 6 | e0 (FEN row 9, col 4) | e9 (FEN row 0, col 4) | ✅ 同列 | ✅ 有2子阻隔 |
| 7 | e1 (FEN row 8, col 4) | e9 (FEN row 0, col 4) | ✅ 同列 | ✅ 有黑卒阻隔 |
| 8 | d1 (FEN row 8, col 3) | e9 (FEN row 0, col 4) | ❌ 不同列 | ✅ 消除 |

**结论**：§4 的修复方案已自然消除所有白脸将违规。帅移到 d1（col 3）后不再与黑将（col 4）同列。

## 8. 审计结论

commit 16a732e 的"一刀切补帅"方式暴露了教程设计的系统性缺陷：
1. **白脸将违规**（P0）：课3和课4补帅后帅将同列且中间全空，产生非法局面
2. **炮架路径冲突**（P0）：课5补帅后 e 线有 2 个棋子，炮的翻山规则失效

两者根因相同：补帅位置 (e1) 与教学核心棋子同在 e 列，没有逐课验证合法性。

**必修项**：课3/课4/课5 的 P0 问题（非法局面 + 教学失效）
**强烈建议**：课3/课6/课8 的 P1 问题（影响教学体验和评判公平性）
**可选优化**：课4 的 P2 精简（不影响功能）

### 关键教训

教程 FEN 设计必须通过以下最小验证清单：
- ✅ 每方恰好 1 个将/帅
- ✅ 帅将在九宫格内
- ✅ **帅将不同列或同列时有棋子阻隔**（白脸将规则）
- ✅ 炮的翻山路径上棋子数正确
- ✅ expectedMoves 在修复后仍为合法唯一走法
- ✅ 棋子不在底线（兵/卒）
- ✅ 总棋子数 ≤ 32
