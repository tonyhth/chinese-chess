## 发现的问题（按严重度 P0-P3 分级）

### P0 — 严重（影响功能或英文用户完全无法理解）

无。

### P1 — 高（英文用户可见的未国际化文本）

#### P1-1: BoardTheme 主题名称硬编码中文，未走 L10n

**文件**：`src/ChineseChess/Services/BoardTheme.swift:17-19`

```swift
case .jadeGreen: return "翡翠绿"
case .imperialGold: return "帝王金"
case .crimson: return "朱砂红"
```

`classicWood` 和 `inkStone` 正确使用了 `L10n.shared.t()`，但 v3.0 新增的三个主题直接硬编码中文。英文用户在设置页看到的是中文主题名。

xcstrings 中已有 `theme.classicWood` 和 `theme.inkStone`，但缺少 `theme.jadeGreen`、`theme.imperialGold`、`theme.crimson` 三个 key。

#### P1-2: BoardTheme 解锁条件描述硬编码中文

**文件**：`src/ChineseChess/Services/BoardTheme.swift:36-39`

```swift
case .classicWood, .inkStone: return "默认解锁"
case .jadeGreen: return "升至秀才段位解锁"
case .imperialGold: return "升至举人段位解锁"
case .crimson: return "升至进士段位解锁"
```

英文用户在主题选择界面看到中文解锁说明，无法理解解锁条件。

#### P1-3: PGNExporter 错误消息硬编码中文

**文件**：`src/ChineseChess/Services/PGNExporter.swift:13-16`

```swift
case .emptyMoves: return "走法列表为空"

`ExportError.errorDescription` 返回中文，英文用户在导入/导出时看到中文错误信息。

#### P1-4: PGNImporter 错误消息硬编码中文

导入解析失败的 warning 消息也是中文（第 85 行 `"第 \(i + 1) 局解析失败：\(error.localizedDescription)"`）。

#### P1-5: PGNExporter 中 `[Site]` 标签硬编码中文

```

PGN 标准中 `[Site]` 和 `[Event]` 的值应为人类可读文本，英文用户导出的 PGN 文件包含中文标签值。

### P2 — 中（不影响核心功能，但影响体验一致性）

#### P2-1: `game.vsAITitle` 占位符不匹配

**xcstrings**：

| Key | en | zh-Hans |
|-----|-----|---------|
| `game.vsAITitle` | `vs AI` | `人机对局 %@` |

英文版没有 `%@` 占位符，中文版有。如果代码通过 `String(format:)` 传参，英文版会丢弃参数；如果不传参，中文版会显示字面 `%@`。

需确认调用方式并统一占位符（要么都加，要么都不加）。

#### P2-2: ChessBoardView 楚河汉界硬编码，重复 xcstrings 定义

**文件**：`src/ChineseChess/Views/ChessBoardView.swift:512-519`

```swift
Text("汉  界")
Text("楚  河")
```

同样的文本在 `ReplayBoardView.swift:168-170` 也有硬编码。

xcstrings 中 `board.chuRiver` 和 `board.hanBorder` 已定义（且英文翻译正确保持了中文原文），但 View 层直接硬编码而非用 `l10n.t("board.chuRiver")`。

当前不影响功能（因为中英文都是"楚河汉界"），但违反了 i18n 规范——如果未来要做更多语言，这些字符串不会被纳入翻译流程。

#### P2-3: OpeningBookExpander 描述硬编码中文

**文件**：`src/ChineseChess/AI/OpeningBookExpander.swift:201`

```swift
description: "中国象棋开局库 v3.1（\(positionCount) 局面）"
```

这是开局库元数据，如果对用户可见（例如在 UI 中展示），需要国际化。

#### P2-4: SettingsView 调试模式描述硬编码中文

**文件**：`src/ChineseChess/Views/SettingsView.swift:137`

```swift
Text("开启后所有功能解锁，方便测试")
```

英文用户在设置页看到中文说明。虽然是调试功能，但违反 i18n 规范。

### P3 — 低（设计决策/风格问题）

#### P3-1: 教程中棋子名称翻译策略

**key**：`tutorial.0.description`

中文版使用棋子本名（车/马/象/炮/兵/士/将帅），英文版翻译为国际象棋对应名称（Rook/Knight/Bishop/Cannon/Advisor/General/Pawn）。

这是一个**合理的翻译策略选择**——教程的目的是让英文用户理解棋子走法，使用 Western chess 类比降低学习门槛。不属于领域语言违规。

但需要注意：`tutorial.0.description` 英文版提到了 `Rook`、`Knight` 等词，而棋盘上实际显示的是中文棋子（帅仕相馬車炮兵）。对于纯英文用户，可能产生认知割裂。

**建议**：可以考虑在英文教程描述中同时标注中文原字，如 `"🔴 車 (Rook) moves in straight lines"`，但这属于体验优化，非必须。

#### P3-2: 语言选择器中 `"中文"` 标签

**文件**：`src/ChineseChess/Views/SettingsView.swift:65`

```swift
Text("中文").tag("zh-Hans" as String?)
Text("English").tag("en" as String?)
```

语言选择器用各自语言显示名称是行业惯例（就像 iOS 系统设置中 "简体中文" / "English"），**不算 bug**。

#### P3-3: xcstrings 中 228 个 key 未在代码中直接引用

544 个 key 中有 228 个未通过 `l10n.t("key")` 直接引用。分析原因：

- **achievement.* (99 keys)**：通过 `achievement.{id}.name` / `.desc` 动态拼接 key 查找
- **daily.* (部分)**：通过 `DailyChallengeMode.localizedTitleKey` 动态拼接
- **rank.* / rank.privilege.***：通过 `Rank.localizedTitleKey` 等动态拼接
- **其他**：部分通过 `UnlockedFeature.localizedKey` 等间接引用

这些不是真正"未使用"，而是通过动态 key 构造使用。系统设计合理，不需要修改。但缺少静态引用检查意味着如果 key 拼写错误，编译期无法发现。

## 建议改进

### 1. 补全 BoardTheme 国际化（修 P1-1, P1-2）

在 xcstrings 中新增 6 个 key：

| Key | en | zh-Hans |
|-----|-----|---------|
| `theme.jadeGreen` | Emerald | 翡翠绿 |
| `theme.imperialGold` | Imperial Gold | 帝王金 |
| `theme.crimson` | Cinnabar | 朱砂红 |
| `theme.unlockDefault` | Unlocked by default | 默认解锁 |
| `theme.unlockRank` | Reach %@ rank to unlock | 升至 %@ 段位解锁 |

BoardTheme.swift 改为 `L10n.shared.t()` 调用。

### 2. PGN 导出/导入错误信息国际化（修 P1-3, P1-4, P1-5）

PGN 标签值虽然是元数据，但既然要支持英文用户，应考虑：
- 错误消息走 `L10n.shared.t()`
- `[Site]` 标签可以用 app 名称的对应翻译，或固定用 `Chinese Chess`（英文通用名）

### 3. 消除 ChessBoardView 楚河汉界硬编码（修 P2-2）

将 `Text("楚  河")` 改为 `Text(l10n.t("board.chuRiver"))`，确保所有用户可见文本统一走 L10n 管道。

### 4. 修复 game.vsAITitle 占位符不匹配（修 P2-1）

统一中英文的占位符。如果该 key 需要传 AI 难度名称作为参数，英文版应改为 `vs AI (%@)` 或 `vs %@ AI`；如果不需要参数，中文版应去掉 `%@`。

### 5. 考虑添加 i18n 测试断言

现有测试 `UIBugI18nTests.swift:89` 检查 `String(localized:)` 键在 xcstrings 中存在，但项目中实际使用的是 `l10n.t()` 模式，该测试覆盖不到。建议新增测试：
- 遍历所有 `l10n.t("literal")` 调用，验证 key 存在于 xcstrings
- 验证所有 key 的 en + zh-Hans 都有值（当前已满足，加入回归保护）

### 领域语言硬性检查结论

✅ **通过**。中国象棋核心术语在英文界面中正确保持中文不翻译：
- 棋盘文字 `楚河汉界`：英文版保持 `楚  河` / `汉  界`（xcstrings `board.chuRiver` / `board.hanBorder`）
- 棋子字符 `帅仕相馬車炮兵` / `将士象馬車砲卒`：`Piece.displayName` 硬编码中文，不走 i18n，正确
- 中文棋谱记号（`炮二平五` 等）：`NotationGenerator` 硬编码中文棋子名和纵线编号，这是中文记谱法本身的要求，正确
- 段位名称在英文中使用意译（Scholar/Graduate/Master 等），属于合理的本地化策略，因为这些是中国古代科举名衔，直接用中文英文用户无法理解

### 总体评价

项目的 i18n 基础设施质量**良好**。L10n 运行时切换机制设计合理（bypass 系统本地化，直接从 xcstrings 加载翻译表），544 个 key 实现了中英双语全覆盖。主要短板在 BoardTheme 和 PGN 导出/导入两个模块，存在硬编码中文字符串遗漏。领域语言处理完全符合要求。修复 5 个 P1 问题后可达国际化生产级标准。
