## P0 发现

### P0-1：UnifiedSheetTests 断言与实际枚举不同步

- **文件**: Tests/UnifiedSheetTests.swift:40, App/ChineseChessApp.swift:68-83
- **级别**: P0
- **问题**: `SheetDestination` 枚举已有 15 个 case，但 `testSheetDestination_AllCases` 仍断言 `ids.count == 12`。v3.7.2 新增的 `.analysis`、`.coach`、`.openingExplorer` 三个 case 完全无测试覆盖。测试通过是假阳性——它验证的是一个过时的 case 数量。
- **建议**: 断言改为 15，并补上 3 个新 case 的 id 验证。

### P0-2：和棋检测"伪覆盖"——测试存在但结构上不可能失败

- **文件**: Tests/DrawDetectionTests.swift（Phase 1 部分 + DrawDetectionIntegrationTests 部分）
- **级别**: P0
- **问题**: DrawDetectionIntegrationTests 的 5 个 @Test 全部是伪覆盖：
  1. `testNewGameClearsFingerprints`：只检查 FEN 非空和包含 `" w "`，不验证 fingerprint 计数清零
  2. `testInitialFingerprintHasTurn`：`fen.contains(" w ") || fen.contains(" b ")` — 或逻辑，任何 FEN 都通过
  3. `testFingerprintChangesAfterMove`：`if ... { #expect(true) } else { #expect(true) }` — **两分支都 pass，结构上不可能失败**
  4. `testPerpetualCheckThreshold`：`#expect(6 % 2 == 0)` 和 `#expect(6 / 2 == 3)` — 纯算术，与源码无关
  5. `testInitialState`：检查 `gameState == .playing`，与和棋检测无关

  **比"没有测试更危险"**：这些测试制造了"和棋检测已被验证"的假象。CI green 的前提下，开发者不会审视实际逻辑。

  **补充（Vera 发现）**：DrawDetectionTests 的 Phase 1 部分同样有问题——`detectPerpetualCheckAlgorithm(moves:)` 是测试文件内**重新实现的算法副本**，不是调用 `GameViewModel.detectPerpetualCheck()`。即使 GameViewModel 的实现有 bug，测试也不会失败（因为测的是 mock 实现）。
- **建议**: 
  - 删除或重写 DrawDetectionIntegrationTests，改为真正调用 GameViewModel 的 checkGameState，验证 gameState 变为 .draw
  - 移除测试文件内的算法副本，直接测试源码方法
  - 可能需要提升 GameViewModel 的可测试性（提取 checkGameState 为可注入方法）

### P0-3：13 个源文件零测试覆盖

- **文件**: AI/KingSafetyEvaluator.swift (235行), AI/OpeningBookExpander.swift (283行), AI/CMAESOptimizer.swift (526行) 等 13 个文件
- **级别**: P0
- **问题**: 13 个源文件（含核心 AI 逻辑）完全没有对应测试文件。KingSafetyEvaluator 和 OpeningBookExpander 是影响 AI 走棋质量的核心组件。
- **建议**: 按优先级补测试：KingSafetyEvaluator > OpeningBookExpander > CMAESOptimizer > 其余

### P0-4：CoachExplainer.isSafeCapture 永远返回 false

- **文件**: AI/CoachExplainer.swift:206-211
- **级别**: P0（v2 升级：原 P1-1）
- **问题**: `isSafeCapture` 直接 `return false`。由于调用点 `:104` 的条件 `if isSafeCapture(bestMove, fen: fenBefore)` 永远为 false，`.missedCapture` 教学路径**完全静默**。
- **影响面精确描述**（Vera 修正）：CoachExplainer 仍有 7 个其他 return 路径（`.blunder`、`.missedMate`、`.missedCheck`、`.developPiece`、`.defensiveMove`、`.centerControl`、`.generic`），功能没有完全瘫痪。但 `.missedCapture`（错过吃子机会）是教练功能的一个重要教学维度——用户永远不会被提示"你错过了一个吃子机会"。这是六分之一的教学路径完全静默。
- **建议**: 实现 isSafeCapture 的真正逻辑（需要 Board 推演判断走法是否为吃子且吃子后不被反吃），或暂时删除 `.missedCapture` case 避免死代码。

## P1 发现

### P1-1：EndgameEvaluator 84 条规则仅测 4 个局面

- **文件**: Tests/Phase7Tests.swift, AI/EndgameEvaluator.swift
- **级别**: P1（维持——Vera 不同意升 P0）
- **问题**: EndgameEvaluator 有 84 条 `.init(...)` 规则定义，Phase7Tests 仅测了 4 种简单局面。84 条规则中任何一条的 rawValue 写错或 pattern 匹配逻辑有 bug，测试不会发现。
- **不升 P0 的理由**（Vera 分析）：EndgameEvaluator 是 AI 估值的一部分，不是用户直接交互的功能。84 条规则是参数化的（同模式 redPattern/blackPattern/score 三元组），单条错误只导致 AI 走棋微弱偏差。endgameNoCrash 已验证基本健壮性。
- **建议**: 用参数化测试遍历所有 84 条规则，验证每种局面返回非零分数。

### P1-2：测试文件中重新实现算法逻辑而非调用源码

- **文件**: Tests/DrawDetectionTests.swift（detectPerpetualCheckAlgorithm 是 mock 实现）
- **级别**: P1（Vera 新增遗漏）
- **问题**: 测试文件内重新实现了 `detectPerpetualCheck` 算法逻辑，而非调用 `GameViewModel.detectPerpetualCheck()`。这种模式如果普遍存在，说明测试方法论有系统性问题——测试验证的是"算法副本的正确性"而非"源码的正确性"。
- **建议**: 排查其他测试文件是否存在类似模式。移除算法副本，直接测试源码方法。

### P1-3：Phase7Tests.endgameRuleCount 名不副实

- **文件**: Tests/Phase7Tests.swift
- **级别**: P2（Vera 新增遗漏，我定为 P2 而非 P1）
- **问题**: `@Test("残局评估器扩展到 50+ 种规则")` 测试名声称验证"50+ 规则"，但实际只测了 2 种局面。
- **建议**: 重命名测试或补充实际覆盖。

### P1-4 ~ P1-8：其余 P1 发现

维持 Tina 原始审计中的 P1 发现，Vera 复核无异议。
