## 一、背景

### 1.1 问题

当前 AI 难度为 5 级（beginner/easy/medium/hard/master），使用两套引擎：
- 自研 AIEngine（beginner~master）：depth-1~10，手写启发式评估，棋力 ~600-1800 Elo
- Pikafish（beginner~master）：depth 2/5/10/18/24，NNUE 神经网络评估，棋力 ~2000-3300 Elo

**核心矛盾**：
1. Pikafish 即使最低级别（depth 2），用户（业余水平）也无法战胜——NNUE 评估太强
2. depth 不能可靠控制棋力——depth=1 只搜索 quiescence（反而比 depth=2 强），depth ≤ 5 棋力混沌
3. 自研引擎与 Pikafish 之间有 ~200-400 Elo 的空白区间（1800-2000+），是象棋爱好者最集中的段位

### 1.2 关键决策（洪涛确认）

| # | 决策 | 理由 |
|---|------|------|
| 1 | 10 级统一棋力梯度 | 覆盖入门到棋圣完整区间 |
| 2 | 业余级（1-5）自研引擎 | "走法像人的弱对手"更重要 |
| 3 | 专业级（6-10）Pikafish Skill Level | depth 不可靠，Skill Level 有天梯校准 |
| 4 | 恢复 Skill Level 支持 | 从 Stockfish 上游移植，官方天梯数据可信 |
| 5 | iOS 不可关闭 Pikafish | 两个引擎都要开启 |
| 6 | 难度不加段位门禁 | 自由选择是对弈核心体验 |
| 7 | 不存在存档兼容问题 | v6.0 为全新版本，当前仅一个用户 |
| 8 | 新增棋力评估功能 | 六维评估，帮用户定位自己的水平 |

### 1.3 为什么不用 depth 控制棋力

**depth 限制的本质是限制搜索树深度**，但低 depth 时行为非单调：

| depth | 搜索行为 | 棋力表现 |
|-------|---------|---------|
| 1 | 纯 quiescence（只搜吃子走法） | 反常——"吃子直觉"避开了不完整搜索陷阱 |
| 2 | 1 层 negamax + quiescence | 弱于 depth 1（horizon effect 误导） |
| 5 | 5 层 negamax | 棋力开始稳定但无法精确控制 |
| 8+ | 完整搜索 | 棋力与 depth 大致线性 |

**Skill Level 的原理完全不同**：
1. 完整深度搜索（不限制 depth）→ 走法质量有保证
2. 开启 MultiPV=4 收集前 4 个候选走法
3. 按 Skill Level 从候选中**故意选劣变**（走法质量可控的"犯错"）
4. 官方天梯校准数据：Skill 0 = 1280 Elo，Skill 20 ≈ 3300 Elo

**depth = "看不到好走法"；Skill Level = "看到但故意走差"。后者才是正确的棋力控制方式。**

## 三、10 级棋力梯度设计

### 3.1 核心架构

```
级别 1-5：自研 AIEngine（走法像人，棋力 ~600-1800）
级别 6-10：Pikafish Skill Level（天梯校准，棋力 ~1280-3300）

EngineRouter 按难度自动路由：
  amateur 级别 → AIEngine.bestMove()
  professional 级别 → EmbeddedPikafishEngine.bestMove(skill=...)
```

### 3.2 10 级参数表

| 级别 | 名称 | 引擎 | 引擎参数 | 预估 Elo | 目标用户 |
|------|------|------|---------|----------|---------|
| 1 | 入门 | 自研 | depth-1 + ±150cp 噪声 + top-5 加权随机 | ~600 | 初学者 |
| 2 | 初级 | 自研 | depth 3 | ~900 | 入门后练习 |
| 3 | 业余初级 | 自研 | depth 5-6 | ~1200 | 一般爱好者 |
| 4 | 业余中级 | 自研 | depth 6 + 杀棋搜索(12层) | ~1500 | 业余棋手 |
| 5 | 业余高级 | 自研 | depth 7-10 + 杀棋搜索(16层) + 开局库 | ~1800（待校准） | 进阶爱好者 |
| 6 | 业余初段 | Pikafish | Skill Level 0 | **1280（待校准）** | 待定 |
| 7 | 业余三段 | Pikafish | Skill Level 4 | **1777** | 业余中级 |
| 8 | 业余五段 | Pikafish | Skill Level 8 | **~2400** | 业余高手 |
| 9 | 专业三段 | Pikafish | Skill Level 13 | **2850** | 专业棋手 |
| 10 | 棋圣 | Pikafish | Skill Level 20 | **~3300** | 无限制 |

### 3.3 过渡区分析（5级 → 6级）——⚠️ 待校准

**注意：自研引擎和 Pikafish Skill Level 的实际 Elo 均未校准，以下分析基于推断值，最终切分点待交叉对弈验证后确定。**


| 维度 | 5级（自研 master） | 6级（Pikafish Skill 0） |
|------|-------------------|----------------------|
| 预估 Elo | ~1800 | ~1280 |
| 走法风格 | 手写评估，走法"像人" | NNUE 评估 + 劣变选择，走法"会犯错但不是低级错误" |
| 用户体验 | 用户能赢 | 用户也能赢（1280 Elo < 用户水平） |

**注意**：6级（Skill 0，1280 Elo）实际上比 5级（自研 master，~1800 Elo）弱。这是设计意图——5级到6级不是简单的棋力递增，而是引擎切换点。用户从 5级（自研引擎上限）过渡到 6级（Pikafish 最低档）时，会发现"换了一种风格的对手"，棋力可能略降但走法质量不同。

**后续优化**：可以通过 Skill Level 精细调节（如 Skill 3-5）找到与自研 master 棋力对齐的点，确保过渡更平滑。

## 四、技术实现

### 4.1 AIDifficulty 枚举改造

```swift
enum AIDifficulty: String, CaseIterable, Codable {
    // 业余级（自研引擎）
    case novice        // 1级 入门
    case beginner      // 2级 初级
    case amateurLow    // 3级 业余初级
    case amateurMid    // 4级 业余中级
    case amateurHigh   // 5级 业余高级

    // 专业级（Pikafish Skill Level）
    case amateurDan    // 6级 业余初段 (Skill 0)
    case proApprentice // 7级 业余三段 (Skill 4)
    case proExpert     // 8级 业余五段 (Skill 8)
    case proMaster     // 9级 专业三段 (Skill 13)
    case grandmaster   // 10级 棋圣 (Skill 20)

    var isProfessional: Bool {
        switch self {
        case .amateurDan, .proApprentice, .proExpert, .proMaster, .grandmaster:
            return true
        default:
            return false
        }
    }

    var skillLevel: Int? {
        switch self {
        case .amateurDan:    return 0
        case .proApprentice: return 4
        case .proExpert:     return 8
        case .proMaster:     return 13
        case .grandmaster:   return 20
        default:             return nil  // 业余级不使用 Skill Level
        end
    }
}
```

### 4.2 EngineRouter 路由

```swift
func bestMove(for board: Board, difficulty: AIDifficulty, ...) async -> Move? {
    if difficulty.isProfessional {
        // 专业级：Pikafish + Skill Level
        let engine = await switchEngineIfNeeded()
        if let pikafish = engine as? EmbeddedPikafishEngine {
            pikafish.setSkillLevel(difficulty.skillLevel!)
            return await pikafish.bestMove(...)
        }
        // Pikafish 不可用时 fallback 到自研 master
        return await nativeEngine.bestMove(for: board, difficulty: .amateurHigh, ...)
    } else {
        // 业余级：自研引擎
        return await nativeEngine.bestMove(for: board, difficulty: difficulty, ...)
    }
}
```

## 五、棋力评估功能

### 5.1 目标

帮用户定位自己的棋力水平，推荐合适的对弈级别。评估不依赖用户与各级别 AI 对弈（用户连最低级别都赢不了），而是通过分析用户对局质量来估算。

### 5.2 六维评估体系

| 维度 | 评估方法 | 数据来源 | 权重 |
|------|---------|---------|------|
| **棋力等级（Elo）** | 逐手走法 delta 分布 → 拟合 Elo | PositionAnalyzer | 核心 |
| **开局水平** | 前 15 步与 OpeningBook 匹配率 | OpeningBook 比对 | 15% |
| **中盘战术** | 精妙/好/普通/失误/漏着 占比 | PositionAnalyzer 六级标注 | 25% |
| **残局功底** | 残局阶段走法质量 + 胜率 | EndgameEvaluator | 20% |
| **稳定性** | 连续好棋/连续失误的波动率 | 逐手 delta 序列标准差 | 20% |
| **杀棋敏感度** | 将杀机会发现率 | CheckmateSearch 比对 | 20% |

### 5.3 评估流程

```
用户进入"棋力评估" → 选择对弈或分析历史对局
│
├── 方式 A：新对弈
│   └── vs 3级（业余初级），1-3 局
│       每局结束后逐手分析
│
├── 方式 B：分析历史对局
│   └── 选择最近 5 局 vs AI 的对局
│       批量逐手分析
│
└── 评估报告
    ├── Elo 估算（±150 置信区间）
    ├── 六维雷达图
    ├── 优势/短板分析
    ├── 推荐对弈级别（1-10）
    └── 推荐训练方向
```

### 5.4 Elo 估算原理

对每一步走法，用 PositionAnalyzer 计算与引擎推荐最优走法的 delta（centipawn）：

```
delta 分布 → Elo 估算映射：
  平均 delta ≤ 30cp + 失误率 < 15%  → ~2000+ Elo
  平均 delta ≤ 50cp + 失误率 < 25%  → ~1500-2000 Elo
  平均 delta ≤ 100cp + 失误率 < 40% → ~1000-1500 Elo
  平均 delta > 100cp 或失误率 > 40%  → < 1000 Elo
```

注：Elo 估算需要 ≥ 60 步样本（约 2-3 局）才能达到 ±150 的置信区间。
