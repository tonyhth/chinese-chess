## 一、产品愿景

用户打开 App → 棋力评估（分析对局估算 Elo）→ 推荐合适的级别（1-10）→ 在该级别对弈 → 积累数据 → 评估精度提升。

两个功能本来就是一个闭环，合并设计、合并评审、合并发布。

## 二、10 级棋力梯度

### 2.1 核心架构

```
级别 1-5：自研 AIEngine（走法像人，棋力 ~600-1800）
级别 6-10：Pikafish Skill Level（天梯校准，棋力 ~2000-3300）

EngineRouter 按难度自动路由
```

### 2.2 为什么不用 depth 控制棋力

depth 限制搜索树深度，低 depth 时行为非单调（depth 1 只搜 quiescence，反而比 depth 2 强）。Skill Level 是完整搜索后按概率选劣变，可控且有天梯校准数据。

> **v4.1 注（P1-2）**：业余级 1-5 仍用自研引擎的 depth 控制，但 1 级例外（见参数表）。自研引擎的 depth 在 3-10 范围内行为单调可控（已验证），问题仅出在 depth ≤ 2 区域。3 级（depth 5）和 4 级（depth 7）现已拉开 2 层差距 + 4 级增加杀棋搜索，区分度充分。

### 2.3 10 级参数表

> Elo 为预估值。业余级基于自研引擎交叉对弈经验，专业级基于 Pikafish 天梯 Elo 保守折算（引擎 Elo 偏高 200-400）。所有值待交叉对弈校准确认。

| 级别 | 名称 | 引擎 | 引擎参数 | 预估人类 Elo | 目标用户 |
|------|------|------|---------|-------------|---------|
| 1 | 入门 | 自研 | top-5 加权随机 + ±150cp 噪声（不限制 depth） | ~600 | 初学者 |
| 2 | 初级 | 自研 | depth 3 | ~900 | 入门后练习 |
| 3 | 业余初级 | 自研 | depth 5 | ~1200 | 一般爱好者 |

>
> **如果交叉对弈显示 5→6 级确实倒挂**：启动 Plan B，6 级改用 Skill 7（天梯 ~2268，折算后 ~1900）。

#### 5→6 级过渡策略

**主方案**：6 级使用 Skill Level 5（天梯 ~1900，折算后预估人类 ~1600），配合 5 级（自研 ~1800）形成过渡。

> **关于 Elo 折算**：Pikafish 天梯 Elo 是引擎自对弈 Elo，系统性地高于人类棋手 Elo。6 级 Skill 5 天梯值 ~1900 看似比 5 级 ~1800 强，但折算后可能反而略弱。这不是设计缺陷——自研引擎和 Pikafish 走法风格不同（启发式 vs NNUE），Elo 标尺不同。交叉对弈会给出真实答案。

**校准计划**：Skill Level 恢复后，执行交叉对弈验证（自研 master vs Pikafish Skill 5，≥10 局）：
- 若 Elo 差 < 100 → 5→6 级梯度过小，6 级上调到 Skill 7
- 若 Elo 差 200-400 → ✅ 合理过渡，确认 Skill 5
- 若 Elo 差 > 500 → 5→6 级跨度过大，6 级下调到 Skill 3

**Plan B（如果 Skill Level 校准后仍不理想）**：
- 6 级固定为 Skill 7（天梯 ~2268，折算后 ~1900），确保严格高于 5 级
- 或在 UI 标注「引擎切换点」让用户理解风格差异
- 优先用校准数据决定

## 三、棋力评估功能

### 3.1 目标

帮用户定位棋力水平，推荐合适的对弈级别。不依赖用户对弈各级别（用户连最低级别都赢不了），而是通过分析对局质量估算 Elo。

### 3.2 六维评估体系

| 维度 | 评估方法 | 数据来源 | 权重 |
|------|---------|---------|------|
| **棋力等级（Elo）** | 逐手走法 delta 分布拟合 | PositionAnalyzer | 核心 |
| **开局水平** | 前 15 步与 OpeningBook 匹配率 | OpeningBook | 15% |
| **中盘战术** | 精妙/好/普通/失误/漏着 占比 | PositionAnalyzer 六级标注 | 25% |
| **残局功底** | 残局走法质量 + 胜率 | EndgameEvaluator | 20% |
| **稳定性** | 逐手 delta 序列标准差 | delta 序列分析 | 20% |
| **杀棋敏感度** | 将杀机会发现率 | CheckmateSearch | 20% |

### 3.3 Elo 估算原理

对每步走法计算与引擎推荐最优走法的 delta（centipawn）：

```
保守公式：Elo = 2500 - 120 × ln(平均 delta)
置信度：< 40 步 = low，40-79 步 = medium，≥ 80 步 = high
95% CI：±150 Elo（high confidence 时）
```

> **v4.1 修订（P1-3）：中国象棋校准说明**
> 此公式参考 chess.com CAPS2 和 Lichess 的 eval→Elo 映射方法，但两者基于国际象棋数据。中国象棋的 centipawn 含义与 NNUE 模型与国际象棋不同，直接套用可能存在系统性偏差。
> 
> **UI 要求**：评估报告中的 Elo 必须标注「估算值，仅供参考」，置信区间必须显著展示。首版以收集数据为主，收集 20+ 用户对局后做线性回归校准。
> 
> 此风险已在 §七 风险表中列出。

### 3.4 评估流程

```
用户进入"棋力评估"
├── 方式 A：新对弈 vs 3级（业余初级），1-3 局
├── 方式 B：分析历史对局（最近 5 局 vs AI）
│
└── 逐手分析（PositionAnalyzer 批量分析，0.6s/步）
    ├── Elo 估算（±150 置信区间）
    ├── 六维雷达图
    ├── 优势/短板分析
    ├── 推荐对弈级别（映射到 1-10 级）  ← 直接输出到 10 级选择
    └── 推荐训练方向
```

### 3.5 推荐级别映射

| Elo 范围 | 推荐级别 | 说明 |
|----------|---------|------|

## 四、技术实现

### 4.1 AIDifficulty 枚举改造

> **v4.2 修订（P0）：rawValue 存档兼容**
> v4.1 使用 case 名作为 rawValue（`novice/beginner/amateurLow/...`），但旧版 `beginner` 的 rawValue 冲突（旧版 = 最低级新手，新版 = 2 级初级）。v4.2 采用选项 A：rawValue 改为 `lvl1-lvl10`，通过自定义 Codable init 做显式旧值映射。

```swift
enum AIDifficulty: String, CaseIterable, Codable {
    // 业余级（自研引擎）
    case novice        // 1级 入门
    case beginner      // 2级 初级
    case amateurLow    // 3级 业余初级
    case amateurMid    // 4级 业余中级
    case amateurHigh   // 5级 业余高级

    // 专业级（Pikafish Skill Level）
    case amateurDan    // 6级 业余初段 (Skill 5)
    case proApprentice // 7级 业余三段 (Skill 8)
    case proExpert     // 8级 业余五段 (Skill 12)
    case proMaster     // 9级 专业三段 (Skill 16)
    case grandmaster   // 10级 棋圣 (Skill 20)

    // v4.2: rawValue 使用 lvl1-lvl10，避免与旧枚举冲突
    var rawValue: String {
        switch self {
        case .novice:        return "lvl1"
        case .beginner:      return "lvl2"
        case .amateurLow:    return "lvl3"
        case .amateurMid:    return "lvl4"
        case .amateurHigh:   return "lvl5"
        case .amateurDan:    return "lvl6"
        case .proApprentice: return "lvl7"
        case .proExpert:     return "lvl8"
        case .proMaster:     return "lvl9"
        case .grandmaster:   return "lvl10"
        }
    }
    
    // v4.2: 自定义初始化，处理新 rawValue + 旧值映射
    init?(rawValue: String) {
        // 新 rawValue 直接映射
        let newMap: [String: AIDifficulty] = [
            "lvl1": .novice, "lvl2": .beginner, "lvl3": .amateurLow,
            "lvl4": .amateurMid, "lvl5": .amateurHigh, "lvl6": .amateurDan,
            "lvl7": .proApprentice, "lvl8": .proExpert, "lvl9": .proMaster,
            "lvl10": .grandmaster
        ]
        if let difficulty = newMap[rawValue] { self = difficulty; return }
        
        // v4.2: 旧枚举值兼容映射
        let legacyMap: [String: AIDifficulty] = [
            "beginner": .novice,       // 旧 beginner（最低级）→ 新 1 级
            "easy":     .beginner,     // 旧 easy → 新 2 级
            "medium":   .amateurLow,   // 旧 medium → 新 3 级
            "hard":     .amateurMid,   // 旧 hard → 新 4 级
            "master":   .amateurHigh   // 旧 master → 新 5 级（不升到 6 级）
        ]
        if let difficulty = legacyMap[rawValue] { self = difficulty; return }
        
        return nil
    }

    var isProfessional: Bool { ... }
    var skillLevel: Int? { ... }
    
    var fallbackToAmateur: AIDifficulty { .amateurHigh }
}
```

> **关键设计点**：
> - `init?(rawValue:)` 中先查新映射，再查旧值映射，保证向后兼容
> - 旧存档 `"beginner"` → `.novice`（1 级），**不是** `.beginner`（2 级）——避免用户被悄悄升级
> - 旧 `"master"` → `.amateurHigh`（5 级），不升到 `.amateurDan`（6 级）
> - 新存档统一写入 `lvl1-lvl10`，不再使用语义化 case 名作为存储格式
>
> **v4.2 补充（Tina P1-1）：Codable fallback 策略**
> `init?(rawValue:)` 返回 nil 时，`JSONDecoder` 解码会失败。为确保旧/损坏存档不崩溃，实现 `init(from decoder:)`：
> ```swift
> init(from decoder: Decoder) throws {
>     let container = try decoder.singleValueContainer()
>     let raw = try container.decode(String.self)
>     if let value = Self(rawValue: raw) { self = value }
>     else { self = .amateurMid }  // 未知值安全 fallback 到 4 级
> }
> ```
> 测试计划维度 2.6（未知 rawValue → .amateurMid）与此一致。

### 4.2 EngineRouter 路由与 Fallback

业余级 → 自研 AIEngine；专业级 → Pikafish + Skill Level。

> **v4.1 修订（P0-2）：Fallback 机制重设计**
> v4.0 的静默 fallback 已移除。新机制分三层：

#### 层 1：启动检查（进入对弈前）

```swift
func validateEngineAvailability(for difficulty: AIDifficulty) -> EngineAvailability {
    guard difficulty.isProfessional else { return .available }  // 业余级不需要 Pikafish
    
    if embeddedPikafish.isReady {
        return .available
    } else {
        return .unavailable(reason: .engineNotReady)
    }
}
```

- 用户选择专业级（6-10）时，先检查 Pikafish 是否可用
- 不可用 → **进入对弈前拦截**，弹窗提示「引擎未就绪，请选择业余级或稍后重试」
- 不允许进入对弈（而非对弈中途静默降级）

#### 层 2：对弈中途异常处理

如果 Pikafish 在对弈中途 crash 或超时：

```swift
// Pikafish 中途不可用 → 非静默 fallback
func handleEngineFailure(difficulty: AIDifficulty) {
    // 1. 发送用户通知
    NotificationCenter.post(name: .engineFallback, 
        userInfo: ["originalLevel": difficulty])
    // 2. 按难度映射表选择最近的自研级别
    let fallbackLevel = difficulty.fallbackToAmateur
    // 3. 记录错误日志
    ErrorLogger.log(.pikafishFailure, originalLevel: difficulty)
}
```

#### 层 3：Fallback 难度映射表

v4.0 一刀切用 `.amateurHigh` 不合理。v4.1 按最近 Elo 匹配：

| 原专业级 | 原 Skill Level | Fallback 自研级 | 理由 |
|---------|---------------|----------------|------|
| 6 级 (amateurDan) | 5 | 5 级 (amateurHigh) | 最近匹配（~1800 vs ~2000） |
| 7 级 (proApprentice) | 8 | 5 级 (amateurHigh) | 自研上限，最近可用 |
| 8 级 (proExpert) | 12 | 5 级 (amateurHigh) | 自研无对等级别，取上限 |
| 9 级 (proMaster) | 16 | 5 级 (amateurHigh) | 同上 |
| 10 级 (grandmaster) | 20 | 5 级 (amateurHigh) | 同上 |

> 所有专业级 fallback 到 5 级（自研上限 ~1800），因为自研引擎最高就到 5 级。关键是：**fallback 必须发通知 + 记录日志 + 用户可见提示**，不能静默。

#### 用户通知 UI

```swift
// GameViewModel 收到 fallback 通知后的处理
func handleEngineFallback(_ notification: Notification) {
    let originalLevel = notification.userInfo!["originalLevel"] as! AIDifficulty
    
    // 显示用户提示
    errorMessage = "引擎异常，已临时切换到业余高级（5 级）\n原难度：\(originalLevel.displayName)"
    errorMessageType = .warning  // 非 fatal，对弈继续
    
    // 对弈继续，但用户知道发生了什么
}
```

## 九、Pikafish 版本锁定声明（v4.2 新增）

> **v4.2（Vera P1-C）**

**锁定版本**：Pikafish dev-20260615（含 Skill Level 移植，commit 31956f6）

**锁定理由**：Skill Level 的 UCI_Elo 天梯数据与特定 Pikafish 版本的 NNUE 模型绑定。升级 Pikafish（或更新 NNUE 评估文件）会导致同一 Skill Level 对应的实际棋力发生偏移，天梯数据需要重新校准。

**升级策略**：
1. 升级 Pikafish 前必须重新跑 Skill Level 天梯验证（至少 Skill 0/5/8/12/16/20 的交叉对弈）
2. 对比新旧天梯 Elo，如果偏移 > 100 Elo 则需要调整 §2.3 参数表
3. NNUE 评估文件更新同理

**代码约束**：`EmbeddedPikafishEngine` 应在初始化时打印当前版本号和 NNUE 文件哈希，便于调试时确认版本一致性。

## 十、技术实现补充（v4.2 新增）

> **v4.2（第 2 轮审查 P1 补充）**

### 10.1 SelfPlayRunner 混合引擎扩展

交叉对弈校准需要 SelfPlayRunner 支持混合引擎对弈（自研 vs Pikafish）。

**扩展点**：
- 当前 SelfPlayRunner 只支持同引擎自对弈（Pikafish vs Pikafish）
- 需新增：`MixedEngineMatch` 模式，引擎 A 执红、引擎 B 执黑
- 自研引擎适配：实现与 Pikafish 相同的 `BestMoveProvider` 协议
- 时限控制：每步固定 movetime（如 500ms），确保公平

**输出**：W/L/D + 逐步走法记录 + 是否 stalemate/mate

### 10.2 Skill Level UCI 调用链路

```
Swift 层：
  AIDifficulty.skillLevel → Int?
    ↓
  EmbeddedPikafishEngine.setSkillLevel(_ skill: Int)
    ↓
  pikafish_api.h: pikafish_set_skill_level(handle, skill)
    ↓
  C++ 层：
    engine.cpp: setoption name Skill Level value X
    search.cpp: Skill 结构体读取 Skill Level
      → MultiPV 强制设为 max(4, MultiPV)
      → 搜索完成后按 Skill Level 从候选走法中选劣变
      → best_move 返回劣变后的走法
```

**验证点**（Ruby 代码审查已确认）：
- `setoption name Skill Level value X` 正确注册为 UCI 选项
- Skill=20 时走法与无 Skill Level 时完全一致（无劣变）
- Skill<20 时 MultiPV 强制开启，候选走法收集正常

### 10.3 switch 语句迁移策略

源码中 68 处枚举引用主要集中在 6 处 switch 语句：

| 文件 | switch 类型 | 迁移策略 |
|------|-----------|----------|
| GameViewModel | `switch difficulty` → 引擎调用 | 改为 `difficulty.isProfessional` 分支 |
| SettingsView | `switch difficulty` → Picker | 改为 10 级分组 Picker（§4.4） |
| AchievementChecker | `switch difficulty` → 难度阑值 | 重新映射阑值（旧 beginner→lvl1...） |
| StatsManager | `switch difficulty` → 统计 key | 使用 rawValue（lvl1-lvl10）作为 key |
| EndgameSetup | `switch difficulty` → defenderDifficulty | 重新映射星级对应 |
| GameRecord | Codable 编解码 | 自定义 init 处理（§4.1） |

**迁移方式**：自动迁移脚本处理 case 名替换 + 手动审查 6 处 switch 语句逻辑正确性。
