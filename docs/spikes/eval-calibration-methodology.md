# v3.0 评估函数权重校准方法论

## 3.7 权重系统化校准

### 初始权重来源
1. **象棋教科书**：经典棋理（车占肋道、马跳卧槽、炮镇中路）
2. **Pikafish 差异分析**：对比 Pikafish 评估输出（只读分析，不引用代码）
3. **自对弈验证**：通过 SelfPlayRunner 识别评估偏差

### 迭代调整流程

```
初始权重 → 自对弈 100 局 → 分析对局
  → 识别偏差模式（如某棋型加分过高导致冒进）
  → 调整权重 → 再自对弈 → 验证改善
  → 重复 5-10 轮
```

### SPSA（Simultaneous Perturbation Stochastic Approximation）

自动化参数搜索框架：

1. **参数向量 θ**：所有权重系数（子力、位置、棋型、机动性、安全）
2. **目标函数**：自对弈胜率（或 BayesElo 估值）
3. **每轮迭代**：
   - 随机扰动 θ ± Δ（Δ 随迭代递减）
   - 分别用 θ+Δ 和 θ-Δ 运行 N 局自对弈
   - 估计梯度：g = (f(θ+Δ) - f(θ-Δ)) / (2Δ)
   - 更新：θ = θ + α × g
4. **参数**：20-50 轮，每轮 20-50 局，α 和 Δ 递减
5. **约束**：棋型加分 ≤ 子力值 30%

### 冲突检测规则
- 单一棋型加分 ≤ 500（攻击型）/ ≤ 300（防守型）
- 同一子力叠加棋型加分 ≤ 子力基础值 × 30%
- 负加分（惩罚）≤ 子力基础值 × 20%

### 当前状态
Phase 3a/3b 的权重基于棋理经验值，未经大规模自对弈校准。
后续通过 SPSA 自动校准需要独立运行环境（每轮 ~1000 局自对弈）。

## 3.9 外部基准对弈

### 目标
建立可量化的 Elo 基准，与外部引擎对比。

### 方案 A：xiangqi.com 排位赛
1. 在 xiangqi.com 注册 AI 账号
2. 使用 EngineAdapter 通过 UCI 协议对接
3. 排位赛 ≥ 50 局
4. 记录 Elo、胜率、开局/中局/残局表现

### 方案 B：与已知 Elo 引擎交叉对弈
1. 对手引擎： pikafish（只读模式）、ElephantEye 等
2. 通过 UCI 协议自动对弈
3. 每个对手 20 局（交换先后手）
4. 使用 BayesElo 计算估值

### 方案 C：手动测试
1. 在 xiangqi.com 人工创建对局
2. 记录 AI 走法质量和棋评
3. 至少 20 局覆盖不同开局类型

### 当前限制
- 无 UCI 协议适配器（需独立开发）
- 自对弈框架已就绪，但外部对接需要额外工程
- Phase 3b 输出方法论文档，后续按需实施
