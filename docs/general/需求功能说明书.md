## 1. 产品概述

### 1.1 产品定位
一款面向象棋爱好者到进阶棋手的**原生双平台中国象棋应用**。以「能对战、能分析、能学习」为核心闭环：提供从入门到大师级的多档 AI 对手、基于顶级引擎 Pikafish 的复盘分析、以及题库 / 大师对局 / 开局树三位一体的学习体系。

### 1.2 目标用户
- **入门用户**：需要新手引导、低难度 AI、提示教学、闯关式题库建立兴趣。
- **进阶爱好者**：需要高质量对局、复盘分析、开局库研习、残局训练提升棋力。
- **深度用户**：需要大师对局库检索、PGN 导入导出、多变化分析等专业工具。

### 1.3 核心价值
1. **双引擎架构**兼顾「离线轻量」与「顶级棋力」：内置引擎保证低延迟响应，高级引擎提供接近职业水平的分析与对战上限。
2. **学习闭环**：对局 → 复盘分析 → 教练讲解 → 针对性刷题 → 大师局研习，形成完整成长路径。
3. **成长体系**：段位 + 成就 + 每日挑战，驱动长期留存。

## 2. 名词约定

| 术语 | 说明 |
|---|---|
| FEN | 象棋局面标准记谱字符串 |
| PGN | 可移植对局记谱格式，用于导入/导出 |
| ICCS | 国际象棋坐标记谱法（如 h2e2），与中文纵横谱相对 |
| NNUE | 高效可更新神经网络，高级引擎的评估核心 |
| MultiPV | 引擎同时输出多条最优变化 |
| 适情雅趣 | 明代象棋古谱，本题库 551 题的题源 |
| 段位 | 应用内成长等级，共 7 级：**学童 → 秀才 → 举人 → 进士 → 翰林 → 国手 → 棋圣** |
| 闪电局 | 双方各限时的快棋挑战模式 |
| 半着 | 一方走一步为一个半着；一回合 = 两个半着 |

## 3. 典型用户场景

### 场景 S-1：入门用户首次体验
1. 首次启动 App → 弹出新手引导，进入交互式教程；
2. 教程结束 → 以「入门」难度开始第一局人机对战，选中棋子看到合法落点高亮；
3. 卡住时按 ⌘⇧H 获得提示与讲解；
4. 对局结束 → 看到结果覆盖层与自动生成的复盘卡片，段位进度更新。

### 场景 S-2：进阶用户复盘提升
1. 完成一局对战 → 按 ⌘⇧A 进入复盘分析页；
2. 查看评分曲线，定位标注为「失误/败着」的走步；
3. 对关键步查看最佳着法与三条候选变化；
4. 带着问题进入题库对应章节闯关，或到开局浏览器研习相关开局分支。

### 场景 S-3：深度用户日常研习
1. 每日打开 App 完成当日挑战（残局/闪电局/解杀棋等），维持连续打卡；
2. 在大师对局库按开局/棋手/赛事检索棋谱，自动播放并阅读逐句点评；
3. 导出自己满意的对局为 PGN，或导入外部 PGN 棋谱回放研习。

- FR-G-09：Given 出现将死/困毙/认输/超时/长将/长捉任一终止条件，When 条件触发，Then 对局立即结束，覆盖层显示胜负与原因，`selectPiece`/`movePiece` 均拒绝后续走子。

#### 4.4.3 每日挑战（FR-L-15）

每日 0 点刷新一个挑战；完成得分 100，未完成 0；连续打卡解锁奖励。**当前 10 种模式中 6 种已实现，4 种为占位（UI 显示"敬请期待"）。**

已实现模式规则：

| 模式 | 初始局面 | 胜负/规则 | 状态 |
|---|---|---|---|
| 残局 | 按日期从题库选题（同日全用户同题） | 解题规则同题库 | ✅ |
| 闪电局 | 标准开局 | 双方各 5 分钟（连续打卡 30 天起 +60 秒），超时判负 | ✅ |
| 大师挑战 | 标准开局，AI 为大师档 | 落败不清零连续打卡 | ✅ |
| 残局起步 | 从最低难度残局 FEN 开局 | 无可用题目时提示挑战不可用 | ✅ |
| 解杀棋 | 一步杀题目 | 限时 60 秒，一步未将死即判负 | ✅ |
| 炮镇全局 | 标准开局 | 炮不受限；车/马仅可在己方半场移动（跨区吃子除外），违规则提示 | ✅ |

- FR-D-05：Given 旧版本产生的数据，When 升级后首次启动，Then 数据自动迁移完成且内容无损；迁移前存在可用备份，迁移失败时数据可恢复至迁移前状态。

### 4.9 规则完整性（FR-R）

| 编号 | 规则 | 行为描述 | 优先级 | 状态 |
|---|---|---|---|---|
| FR-R-01 | 基本走法 | 全部七种棋子走法 + 吃子 + 特殊限制（蹩马腿/塞象眼/炮架等） | P0 | ✅ |
| FR-R-02 | 将帅对面 | 走子后导致将帅同线无遮挡的，该走子非法 | P0 | ✅ |
| FR-R-03 | 困毙 | 轮走方无合法走法且未被将军，判负 | P0 | ✅ |
| FR-R-04 | 三次重复 | 同一局面第三次出现且双方无长打行为，判和 | P0 | ✅ |
| FR-R-05 | 自然限着 | 连续 100 半着无吃子，判和 | P0 | ✅ |
| FR-R-06 | 长将禁着 | 一方在检测窗口内反复将军且局面重复达到阈值，判长将方负 | P0 | ✅ |
| FR-R-07 | 长捉禁着 | 同一攻击方对同一目标反复捉吃且局面重复达到阈值，判长捉方负 | P0 | ✅ |
| FR-R-08 | 禁着优先 | **长将/长捉判负优先于三次重复判和**：同一重复局面若由长打造成，适用 FR-R-06/07 判负而非 FR-R-04 判和（与通行象棋规则一致） | P0 | ✅ |

**验收标准**
- FR-R-02：Given 某走子落子后将帅同线无遮挡，When 玩家尝试该走子，Then 走子被拒绝、棋子不落位、不构成合法落点高亮。
- FR-R-08：Given 一方连续将军造成局面第三次重复，When 判定触发，Then 判长将方负，而非判和。

## 5. 对局状态机

### 5.1 状态定义

```
        ┌─────────────────────────────────────────┐
        │                playing                   │
        │  （轮到玩家 / AI 思考中 / 被将军提示）      │
        └──────┬──────────────┬──────────────┬────┘
               │ 将死/困毙     │ 三次重复/     │ 认输/
               │ 长将/长捉     │ 100半着      │ 超时
               ▼              ▼              ▼
        ┌──────────┐   ┌──────────┐   ┌──────────────┐
        │ redWon   │   │  draw    │   │ blackWon     │
        └──────────┘   └──────────┘   └──────────────┘
               │              │              │
               └──────────────┴──────────────┘
                              ▼
                    终态：禁走子，可复盘/导出/开新局
```

### 5.2 状态规则
1. 仅 `playing` 状态接受走子输入；进入任一终态后走子一律拒绝。
2. 悔棋仅在 `playing` 状态可用，撤回两个半着（玩家 + AI），**无 redo**。
3. AI 思考期间玩家输入被忽略（思考标志位约束）。
4. 终态后可执行：复盘分析、PGN 导出、开新局；不可执行：走子、悔棋。

## 9. 隐私与数据安全

1. **零数据收集**：应用无服务端、无统计 SDK、无广告组件，不收集、不上传任何用户数据。
2. **本地存储**：全部用户数据（对局记录、题库进度、段位、成就、设置）仅存储于设备本地。
3. **隐私政策**：应用内提供隐私政策页，内容与上述承诺一致。
4. **演进约束**：后续版本如引入任何网络功能（在线对战/云同步/统计），必须同步修订本节并更新隐私政策。

## 11. 约束与依赖

1. **构建工具链**：必须 XcodeGen + xcodebuild，SPM 已废弃（`swift build`/`swift test` 不可用）。
2. **测试约束**：禁止无过滤的全量 `xcodebuild test`；必须 `-skip-testing:EloBaselineTests`（自对弈 5 局 × 30+ 分钟）。
3. **NNUE 依赖**：`pikafish.nnue` 删除或移动即导致高级引擎失效（触发 EX-01 降级），打包与更新时必须校验完整性。
4. **法律约束**：Pikafish 为 GPLv3，以静态库链接；应用不分发修改后的 Pikafish 源码。
