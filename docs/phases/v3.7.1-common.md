### 2.2 数据流向

**导入流程：**
```
用户选择文件 → PGNImporter.parse() → ImportResult
    → ImportViewModel 汇总结果 → 用户确认 → GameRecordStore.batchAdd()
    → GameHistoryView 刷新列表
```

**残局棋谱流程：**
```
PuzzlePlayView 通关 → PuzzleViewModel 生成 GameRecord(source: .puzzle)
    → GameRecordStore.addRecord()（含 puzzleId 去重）
    → GameHistoryView 列表可见
    → 点击进入 ReplayView 回放
```

**导出流程（已有，Phase 3 微调）：**
```
GameHistoryView 选择 → PGNExporter.export() / exportBatch()
    → 剪贴板 / 系统分享 / 文件保存
```

## 三、共用数据模型

### 3.1 GameRecord（已有，无需改动）

Phase 3 不需要新增字段。现有 `source`、`puzzleId`、`initialFEN`、`tags` 已足够覆盖导入和残局场景。

### 3.2 ImportResult（已有，扩展）

```swift
struct ImportResult {
    let records: [GameRecord]
    let warnings: [String]
    let skippedCount: Int    // 跳过的局数（非法走法等）
    let totalGames: Int      // 检测到的总局数
    
    var isSuccess: Bool { !records.isEmpty }
    var hasWarnings: Bool { !warnings.isEmpty }
}
```

**设计决策**：不提供 `init(records:warnings:)` 便利构造器。`skippedCount` 必须从 `parse()` 的实际分割-解析逻辑推算（总局数 - 成功数），而非硬绑 `warnings.count`（一个失败局可能产生多条 warning）。现有 `parse()` 是唯一构造点，直接使用 full init。

### 3.3 ImportSummary（已移除）

Vera 审查指出 ImportSummary 与扩展后的 ImportResult 字段重叠。直接在 ImportResult 上增加 `isSuccess` / `hasWarnings` 计算属性，去掉 ImportSummary，减少冗余类型。

### 3.4 RecordSource（已有，不变）

```swift
enum RecordSource: String, Codable {
    case versusAI     // 人机对弈
    case puzzle       // 残局练习
    case imported     // 导入
    case freePlay     // 自由对弈
}
```

### 4.3 GameRecordStore 批量导入接口（扩展）

```swift
extension GameRecordStore {
    /// 批量添加记录，返回实际新增数量（跳过重复）
    /// 单次 writeQueue.sync 内完成所有写入，只调用一次 persistIndex()
    @discardableResult
    func batchAdd(_ records: [GameRecord]) -> Int {
        writeQueue.sync {
            var added = 0
            for record in records {
                // puzzleId 去重
                if let pid = record.puzzleId,
                   summaries.contains(where: { $0.puzzleId == pid }) {
                    continue
                }
                // 直接操作内存，不逐条 addRecord
                summaries.append(RecordSummary(from: record))
                persistSingleRecord(record)
                added += 1
            }
            if added > 0 {
                persistIndex()
            }
            return added
        }
    }
}
```

**设计决策**（Vera P1-6）：`batchAdd` 在单次 `writeQueue.sync` 内完成所有操作，只写一次 index.json。不循环调用 `addRecord()`（每条都写 index.json，性能差且无原子性）。

## 五、技术选型理由

| 决策 | 选型 | 理由 |
|------|------|------|
| 导入 UI 容器 | SwiftUI Sheet + 自定义 View | 与现有 GameHistoryView 的 sheet 风格一致，不用引入新的导航模式 |
| 文件选择 | iOS: `fileImporter` / macOS: `NSOpenPanel` | 系统原生组件，安全沙盒合规 |
| PGN 解析增强 | 在现有 PGNImporter 基础扩展 | 不引入第三方 PGN 库，保持解析逻辑可控 |
| 残局棋谱生成 | PuzzleViewModel 通关回调 | 最小侵入：已有 `buildSolutionRecord()` 和通关弹窗，只需追加存储逻辑 |
| 来源图标 | SF Symbols | 与现有图标体系一致，无需额外资源 |
| ImportSummary 结构体 | 纯数据模型，不持久化 | 一次性展示，用户确认后丢弃 |

## 六、风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| PGN 格式多样性（中文棋谱 vs ICCS） | 部分外部 PGN 无法导入 | Phase 3 仅支持 ICCS，中文棋谱列为后续迭代 |
| 大文件导入（>100 局）卡顿 | UI 冻结 | 解析放后台 Task，进度条反馈 |
| 残局通关后自动存历史可能重复 | 同一残局多次记录 | Phase 1/2 已实现 puzzleId 去重（A4），直接复用 |
| RecordPanelView 导出按钮布局 bug | 修复时可能影响现有布局 | 单独修复，不与 Phase 3 功能耦合 |
