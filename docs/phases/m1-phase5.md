## 5. A3 区分度已知限制正面处理

**盲区**（known-issues.md:184，v6.1.0 P5 回归承诺兑现处）：A3 自对弈监控拿业务计数器 `[N/M]` 当活性心跳，SIGILL 崩溃后 EXIT:132 死亡证据在日志末行被漏看，STALE 持续到次日。

**P5 覆盖设计**（SPRT 控噪声 + 监控双心跳，不重蹈）：
- **SPRT watcher 独立于引擎进程**：`sprt_eval.py --watch --interval 30` 每 30s 合并重算 LLR，即使引擎崩溃 watcher 仍在运行（不依赖业务计数器）——A3 盲区的结构性根治
- **a3_check.sh 多实例模式**（协议 §4 监控）：pgrep 存活 + 日志 mtime>10min=STALE + tail 进度，由丹妮 cron 10min——双心跳（进程在不在 + 日志新不新），不拿局间计数器当心跳
- **启动顺序**（协议 §4）：watcher 先起 → 引擎后起，避免开局漏计
- **三路独立**（协议 §7）：seed 互异 + 进程间零共享；一路崩溃不影响其他路 LLR 累计——单路 STALE 不污染合并判定

**规则**（known-issues.md 同条）：长任务监控只认"进程在不在 + 日志新不新"。本设计完全兑现。

## 附录：V2 dense remap 五分钟意见（P4 遗留，Luke 指定项）

**结论：审计 2a 成立则不需要额外 remap 层。**

SearchBoardV2 槽位规则注释（现核 :68-74）已实现天然 dense mapping：slot i ↔ id == i 的棋子（id 唯一 0..31，构造时 assert（现核 :87-90：id 越界 :87 / id 重复 :88 / 格双占 :90）校验）。不在场的 id = 死亡槽（象棋棋子只减不增，语义等价）。pieces 数组下标 ≠ id（左右对称位 id 相邻），但 V2 按 id 分配槽位、不按数组序——id==slot 即 dense remap 本身，无需额外间接层。审计 2a（v3.1 phase1-2a-2b-audit.md 精神：id 唯一性 + 位置唯一性构造侧拦截）在 V2 :87-90 assert 已兑现。若审计发现 id 唯一性不成立（当前无证据），才需要引入 remap 层兜底——当前设计成立，意见留档。
