## 0. 定位与度量目标

- **定位**：收尾型小版本。清偿 v6.2 遗留工程债 + 测试基建收编，无新用户面特性。
- **度量目标**：测试逃逸率 5/9 → **<20%**。口径（Vera P1-③ 已定，沿用）：逃逸率 = 逃逸 Bug /（逃逸 + 内测拦截），窗口 = v6.3 全周期；**分母 n<10 时不看比率，逐案定性验收**（每例是否按 L5 回流规约带回归测试），n≥10 才考核 <20%。
- **引擎口径**：双引擎并存按难度路由（业余 1-5 自研 / 专业 6-10 EmbeddedPikafish v3.4.0），无"切换"模型。

## 1. 五层防线总览

把 scope 里的 C/E/L 各项按"逃逸路径上的拦截位置"重组为五层，每层回答一个问题：

| 层 | 防线 | 防什么 | 承载项（scope 编号） |
|---|------|--------|---------------------|
| 一 | **引入防线**（设计/代码面） | 坏口径、坏分支进入代码 | E5 开关退场、C4 #if os() 定性（22 处）、C2 accessibilityLabel |
| 二 | **运行时防线**（引擎/资产面） | 引擎失效以"挂死/空结果"形态逃到用户 | E1 资产前置校验、E2 watchdog 补全、E3 旁路收敛（含 C3 残余核验）、**PA-1 PositionAnalyzer 承接位（新）** |
| 三 | **测试防线**（基建/用例面） | 假绿（没测到）、假红（环境干扰） | C1 XCUITest 收编 + L3 真实性纪律、L2 补桩 + r3 双平台、**SEL-1 SelectionConsistency 26 用例入库（新）**、**H-1 测试卫生治理包（新，吸收 Tina 清单）** |
| 四 | **交付防线**（产物面） | 坏包流出（缺资源/错摘要） | L1+L4 manifest hash 单源两消费、C5 verify_delivery 参数校验、**PKG-1 打包摘要 bug（新）** |
| 五 | **回流防线**（复发面） | 同一类 bug 二次逃逸 | L5 回流规约（修复必带回归测试同 commit）、逃逸率度量、**G-1 GameRecordStore UD 直写 nil 查证（新）** |

> 表注（P3-⑨）：E5 归第一层（引入防线），但执行批次在 Step 2（与 E1-E3 同改引擎面）——「防线分类」与「执行批次」是两个正交轴，勿按表内顺序推执行顺序。

新增五项（PA-1 / SEL-1 / H-1 / PKG-1 / G-1，共五处承接位）均为本任务派单素材，scope 终版时未登记，此处在对应层吸收，工作量增量见 §3。

## 2. 主线执行步骤（≤5 步）

> 洪涛偏好口径：一个人看了就知道怎么干。每步内部并行，步与步之间只有一条依赖链。

**Step 1｜测试卫生治理先行（H-1）——先把跑道清干净**
- 跨 suite L10n 竞态：`.serialized` 不跨 suite 已二次实证，四 suite 混跑出假红指纹 → 落地**互斥跑 + 全局语言锁**，机制选型二选一（Tina 定，不允许第三种自研方案）：
    - **首选 a：脚本编排互斥**——统一 test-runner 脚本持 `flock` 进程锁（锁文件固定路径），所有 suite 起跑前抢锁，抢不到即排队；语言锁由脚本注入启动参数（`-AppleLanguages (-zh-Hans)` 类环境面统一设置），一处定义全员复用。
    - 备选 b：XCTest plan `.serialized` 全局序列化（若实测可跨 suite 生效，则省脚本；但 08-28 实证其不跨 suite，采用前须复测）。
  - 约束条件（两候选通用）：① 锁/语言设置对 r 系长跑批与正式批同样生效，不得只盖测试 suite；② 锁粒度 = 进程级（同机互斥），不追求跨机；③ 排队不得静默丢弃——排队中任务须可查状态；④ 机制选定后写入工单模板，后续新增 suite 默认接入。
  - r3 系基建治理：锁屏挂死 ×2、UILayoutOpt/Pikafish 死锁、并行批干扰 → 按 08-28/08-29 既有裁定执行：卡死套件入常规 skip 集中管理、正式批与 r 系长跑基线**互斥起跑**规约固化进工单模板。
- **Step 1 出口判据（写死，满足才进 Step 2）**：① 四 suite 混跑 ≥3 轮，已知假红指纹（如前 1 英文后 4 中文类 L10n 漂移）零再现；② skip 集中清单落档（含 reason 字段，覆盖已裁定的死锁/挂起套件）；③ 互斥起跑规约 + 语言锁写入工单模板。Tina 起跑轮次、Luke 签收出口。工期按 **0.5–0.75d（Tina）**估，3 轮验证轮次含在上端。
- 为什么第一步：后续所有测试结果的可信度依赖这步；不清跑道，后面每层的验收都是假绿/假红指纹污染。
- **G-1 前置并行**（P2-⑦）：GameRecordStore UD 直写 nil 定性查证（0.25d Cody/Ruby）在本 Step 并行执行，不挂 Step 5；查证属实即生成工单、按根因归第一/二层，保证新增工单落在主线头部而非尾部。

**Step 2｜引擎可靠性（E1→E2→E3→E5，第二层）**
- E1 启动校验 nnue（期望值引 manifest 单源）→ E2 超时治理**全调用点**：bestMove + evaluate + multiPV（含分析/复盘/教练面/回放旁路），统一 15s（evaluate 现行 2s 口径一并复核归一），超时走层 2 降级 → E3 EmbeddedPikafishEngine 全构造点审计收敛过 EngineRouter 单例（顺带消化 C3 残余核验 + v4 原审查逐条对照；审计表把分析/复盘/教练面/回放的分析路径列为独立条目，不并进 bestMove 面）→ E5 useEmbeddedEngine 开关全清（含 iOS Toggle 58b384a、.active 预热线适配、ad9126b 守卫对账）。
- **PA-1 承接（Luke 已裁：真实回归，并入 E2/E3 工单）**：PositionAnalyzer 回归（MultiPV depth=0 / evaluate 2s 超时返回空）正是"分析路径旁路了 watchdog/单例"形态的第二层逃逸样本，症状落在 evaluate 与 multiPV 两条调用路径上——**修复面覆盖 E2 全调用点口径（bestMove + evaluate + multiPV），不得只修 bestMove**。修复 commit 必须带**症状指纹级回归测试**（L5 规约）：至少复现 MultiPV depth=0 与 evaluate 超时返回空两个指纹的用例各一，只带 bestMove 路径用例不算清偿。工时 0.25–0.5d 已入账（见 §3）。

**Step 3｜测试资产入库（第三层）**
- C1：I4I6RegressionUITests 移出 gitignore 正式收编（xcodegen 双工程接入 + 六轮导航链跑通一次），L3 真实性纪律（像素锚必含故障源真实组件 + 关键页面三图入档脚本化）写入 C1 工单验收项。
- SEL-1：SelectionConsistencyTests 26 用例（含 EngineTimeContract 3/3）已完成待入库。**入库口径 Luke 已裁：选 a，随 C1 同批入库**（同为测试资产收编，省一次 target 接入）。工作量 ~0.25d Tina。
- L2/C4 合批：22 处 `#if os()` 定性 + 测试映射一张表出（消化 Eric 底料 `docs/test/platform-branch-matrix.md` 124 处快照），缺桩补桩 + r3 全量批双平台各跑一次。

**Step 4｜交付链防线（第四层）**
- manifest 单源：l10n/字体/开局库/图标/nnue 大小与 hash 一份定义，L1（verify_delivery.sh 侧）与 L4（deploy 侧）两处消费，E1 app 内校验同引一份。
- C5 verify_delivery.sh 参数校验顺手；**PKG-1**：打包脚本摘要 bug 修复——OpeningBook 0 files 误报（v6.2 复盘产出），摘要输出与 manifest 对账，让"0 files"类异常显式 fail 而非静默通过。

**Step 5｜回流规约与收口（第五层）**
- L5 三件：suite 状态复位纪律、skip 集中管理（与 H-1 同根，H-1 落地 L5 收规约）、逃逸 Bug 回流规约入 known-issues + 工单模板。
- G-1：定性查证已前置到 Step 1 并行执行（0.25d Cody/Ruby）；属实生成工单按根因归层，不属实关账。**不在"待查"状态出 v6.3。**
- 逃逸率按 §0 口径在版本收口时结算，n<10 逐案定性报告随 release note 附洪涛。

## 4. 验收标准

1. **逐层验收**：五层各有承载项工单，每工单按 scope 既有验收条款 + 本文新增项（H-1/SEL-1/PKG-1/G-1）验收，工单关账 = 回归测试或对账证据齐。
2. **测试面**：六轮导航链 + 26 用例入库后全绿一次；r3 全量批双平台各一次全绿。**"全绿"口径（对齐 08-16 守门原则）= 绿，或登记 skip（带 reason）**；r3 批含已裁定入常规 skip 的死锁套件（UILayoutOpt / PikafishCAPITests / GameRecordStore_* 等），按 skip 名单豁免不算红。假红指纹项按 H-1 治理后不再现（H-1 出口判据 = 3 轮零指纹，见 §2 Step 1）——治理后若再现，按新问题立案不混入。
3. **引擎面（否定式验收附取证方法，08-16 三跳规约）**：拔 nnue 冷启动 → 启动即标注不可用（E1）；任意分析/复盘路径注入 15s+ 搜索 → 超时降级不挂死（E2）；E3 "全仓无 EmbeddedPikafishEngine 旁路构造点"：取证 = `grep -rn "EmbeddedPikafishEngine(" --include="*.swift"` 全仓，合法构造点仅 EngineRouter 单例一处，逐条对照落入审计表（表结构锚点：文件/行号/构造形态/处置结论四字段 + 分析/复盘/教练面/回放路径单列条目，落档 E3 工单附录）；E5 "useEmbeddedEngine 全仓零残留"：取证 = `grep -rn "useEmbeddedEngine" --include="*.swift" --include="*.plist"` 双仓（主工程+测试）零命中，Ruby 复核清单落档（清单须含上述命令与执行 commit hash）。
4. **交付面**：拔任一 manifest 资产 → verify_delivery 与 deploy 双侧 fail-fast（L1/L4）；OpeningBook 0 files 类摘要异常显式报错（PKG-1）。
5. **度量面**：逃逸率按 §0 口径结算；n<10 附逐案定性报告，n≥10 目标 <20%。
6. **不留悬空**：PA-1 与 G-1 在版本收口前必须"定性 + 处置（修复/工单/关账）"三态之一，禁止"待查"出版。（PA-1 定性已闭环——真实回归、修复在 E2/E3 工单内；G-1 查证前置 Step 1，出口在 Step 1 判据内。）

## 5. 版本范围边界（防蠕变，scope §3 全文沿用 + 增补）

- 不扩 parity 表为检查机制；不新增 XCUITest 用例（只收编存量 + 已完成的 26 用例）；不动 M1 引擎面语义（E1-E3 为可靠性防线例外，动语义即停手报 Luke）；不做 v7 级新特性；M2 不立项（杠杆点论证另出独立文档，不占 v6.3）。
- **增补**：PA-1 若定性修复量 >0.5d，不默认吸入 v6.3，报 Luke 裁决；H-1 只治理已实证的竞态/挂死/干扰三项，不发起测试框架重构。
