### 1.1 E-A：nullmove 浅域激活假说（推荐第一探针）

- **机理**：nullmove 走法在浅树中的 zugzwang 误判——中国象棋存在困毙约束（无子可动非无子可将军），nullmove 假设"放弃一手总是可行"在困毙风险面不成立；d3 主树仅 3 层+QS qDepth=6，nullmove 剪枝的评估截断面占比远高于深搜索引擎（Pikafish depth 12-18 域 nullmove 无害，浅域比例失衡）。**四证据链的深度阶跃（d2→d3）与激活边界（depth≥3）完全重合，时间线吻合度是全部机理候选中最高的**。
- **数据相容性**：P-C 倒挂（med-d3 −17 vs hard-d2）——med-d3（nullmove R=3 激活）反而弱于 hard-d2（不激活），与"激活 nullmove 的配置在 d3 受损"一致；X₃=+17（med-d3 vs hard-d3 双激活，差异收窄）同样相容。
- **探针设计**：nullmove 门控上移 depth≥4（或 --no-nullmove 旗标，Cody 探针级 ~几十行，--no-tt 18b7ccf 同构）→ 重跑 D₂₃ 口径（hard-d3 vs hard-d2 @8000ms，n=20）。
- **双向后果**：D23dd(nn)≥0 → **nullmove 浅域激活坐实 → 修复=一行级门控上移**，hard-d3 复活评估重开（S1 条件复活路径激活）；仍 <0 → nullmove 出清，边界收窄。
- **成本**：旗标 + 1 批 20 局（~30-40 分钟）+ 判读。**经济学：全选项最优**。

### 1.2 E-C：排序状态局内隔离探针（P3-3 边界的终结探针）

- **机理**：F5 确认三表局内跨手存活。history 深度加权（`+= depth*depth`，MoveOrderer L29）在 d3 搜索中的累积权重是 d2 的 1.5² 倍量级，浅域排序面占比高；跨手累积的 killer/countermove 引导可能使 d3 搜索锁定局部排序模式。**与 TT 局内污染（已被 --no-tt 检验否定为主因）同族不同载体，--no-tt 不触及三表——P3-3 残余的精确含义即此**。
- **探针设计**：--no-orderer-state 旗标（局内每手后清三表，或禁用三表更新）→ 重跑 D₂₃ 口径 n=20。
- **双向后果**：≥0 → 排序状态污染坐实（同族 TT 案第二例）→ 修复线=局内清理策略（低成本）或参数化；仍 <0 → **P3-3 边界正式关闭**，"结构性"结论从"TT 排除+排序状态未定"补全为"TT+排序状态双排除"。
- **成本**：同 E-A。**经济学：无论结果都关闭一个未定项，值得做**。注意 Ruby P3-3 原文边界（"ttOff 阴性不能完整否定排序状态污染子假说"）由本探针直接终结。
- **与 E-A 的关系**：正交机理（排序状态 vs 搜索剪枝），可并行或 2×2 组合（若单探针均阴性，组合批 --no-nullmove+--no-orderer-state 可作终局分辨）。

### 1.3 E-B：medNoQS 域内深度梯度（装配分离探针，可选）

- **机理**：hard 独有装配=QS+PVS（AIConstants L95：mediumNoQS 无 QS/PVS，保留 killer+checkExt+LMR+futility）。若负梯度系 QS/PVS 在浅域的行为，medNoQS 域内 d2→d3 梯度应与 hard 域不同。
- **探针**：medNoQS-d3 vs medNoQS-d2（无库无 kill @8000ms）n=20。现有数据缺 medNoQS 域内深度梯度（P-A/B/C/D 全部是跨 config 或 hard 域内）。
- **解释耦合**：medNoQS 保留 nullmove（R=3）——E-B 结果需按 E-A 结果分层解释（E-A 坐实则 medNoQS 域负可归 nullmove；E-A 阴性且 E-B 负 → 装配共同面；E-A 阴性且 E-B ≥0 → QS/PVS 嫌疑坐实）。**建议排在 E-A/E-C 之后**，按前两者结果决定是否需要。

### 1.4 不推荐的重设计选项（如实评估后排除）

| 选项 | 排除理由 |
|---|---|
| 评估函数重调（weights/phase 表按深度分域） | 触碰评估层红线（v6.5 §8 红线域）；成本高（调参+全量回归）；在机理未分辨前属盲调 |
| QS qDepth 浅域参数化（名义 depth 联动） | 参数工程面广（hard/med 两配置×平台×预算域），探针分辨前做=过早优化；E-A/E-B 结果出来后再议 |
| 换搜索框架（迭代加深改异步/蒙特卡洛类） | 超出"重设计选项"合理半径=重写引擎，成本人月级，与弱化链目标（浅域梯度可标定）完全不成比例 |
| 维持现状不探针 | P3-3 悬置+nullmove 假说悬置=结构性结论带双边界，方案 B 重排表缺条件分支输入——省半天探针换一个更弱的终裁包，不划算 |

### 1.5 E 线小结

**推荐探针链：E-A（nullmove 门控）+ E-C（排序状态隔离）两批并行，各 n=20，合计 2 旗标+40 局+半天；E-B 按需二批。** 若 E-A 坐实 → 修复（一行级门控）+ Ruby 全域审 + hard-d3 复活重标定（S1 复活路径）；若全阴性 → 结构性边界补全（TT/排序状态/nullmove 三出清），修复成本不可控的判断坐实，方案 B 走硬。
