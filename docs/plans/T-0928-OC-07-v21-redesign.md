### 关键机理结论（设计必须直面）

1. **噪声非单调**：同 config 同 depth2 下，噪声 120 方 **强于** 噪声 70 方（+108, n=40 复现）。"噪声=弱化"假设在 70-120cp 区间被证伪。可能机理：噪声打破镜像对弈/与 anti-repetition topK=3 选择交互/噪声充当隐式 contempt。**v2.1 必须给出假说并设计消融验证**
2. **G1 归因混杂**：lvl1（简化 minimax config）vs lvl2（hard config）-147——config 差与噪声差混杂，不能归因噪声。**低端若继续用噪声，需同 config 不同噪声消融**（如 hard config 下 400 vs 200）
3. **depth 台阶无分辨率**：唯一台阶 2→3（G3）仅 -35。开局库加权随机 + anti-repetition 选择 + hard 配置下，浅 depth 差被淹没
4. **预算是死轴**（固定浅 depth 下）：depth 早完成，预算差无效（G2 中 lvl3 预算翻倍无效果；G4 中 3000→5000ms 无效果）。终局模块差（lvl5 全量 vs lvl4 浅层地板）也未见信号
5. **和棋率恶化**：G3/G4 各 30% 和棋，其中 moveLimit 500 步拖满占比高——弱化对局拖沓，用户体验问题，v2.1 需反拖机制评估
6. **c 口径**：iOS 预算上调域待 E2 回填后重评（预算已是死轴的前提下，上调域意义存疑——需明说）

## 4. v2.1 设计要求

1. **多轴组合方案**：至少两轴正交可调，每轴单独可消融验证；档距构成表（沿用 §4 风险表格式）+ 每档距的验证判据
2. **低端（lvl1-2）**：噪声可用（G1 方向对），但幅度须 E2 曲线校准 + 同 config 消融去混杂
3. **中段（lvl3-4）**：depth 台阶需重新设计（2→3 无分辨率 → 考虑更陡台阶或换轴：开局库差异化/候选宽度 topK 差异化——topK 是现成机制且与 E3 倒挂机理相关）
4. **顶段（lvl4-5）**：换轴。候选：终局模块档差重设计（当前无信号需归因）/ topK / CheckmateSearch 档差 / 噪声大幅度（E2 若 200-400cp 在 depth3 有效）
5. **E3 倒挂机理假说 + 消融设计**：给出可验证假说（镜像破坏/topK 交互/隐式 contempt 三选一或新假说）+ 最小消融批设计
6. **快标定门槛重设**：v2 的 G1-G4 预演门槛沿用，但判据需加**单调性硬门**（v2.1 每轴贡献必须单调可验）
