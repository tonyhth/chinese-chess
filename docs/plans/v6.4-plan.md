## 4. Phase 3：④ Elo 估算校准（新设计方向）

**问题**：accuracy→Elo 映射曲线从未用真实对局标定（v6.0 校准没跑），玩家 Elo 2011 与 lvl7 自研天花板 500-800 矛盾——映射输出的绝对值不可信。

**方案方向（洪涛定）**：vs 已知等级 lvl3/5/7 实测对局胜率，反推真实区间，校准映射曲线。

**设计要点（架构层）**：

**前置硬门（v0.3 加 P1-1，v0.4 销项，Luke 亲读代码核证）**：evalDelta mate 污染 = **已解于 v6.3.3，无需热修，不开新轨**。数据链真相（Luke 核证备档）：PositionAnalyzer:335 evalDelta 存原始值 ≈99000 是**数据层真值，by design**（与曲线 mate 真值同口径，v6.4 持久化同需）；污染已在**消费侧全归一**——EloEstimator.eloFromDelta（`ec4b9c1`：|delta|≥90000→700 再进 log 映射）+ SixDimensionScorer 三消费点 normalizedDelta，±99000 进不了映射参数；Phase 3 校准输入 = 同一 deltas→eloFromDelta 管线，**校准前已干净**。**校准前置 = v6.3.3 ec4b9c1（已落地，eloFromDelta/SixDimension 消费侧归一 + 指纹回归锢定），勿重修、勿另开热修轨**。与 §0.5 清偿域渲染层 P2/P3 不是一回事，勿混挂。
1. **锚点诚实声明（前置）**：lvl3/5/7 的"已知等级"本身是估带（v6.2 框架：自研上限 500-800，lvl2-5 窄带；M1 后 Pikafish 按难度恒路由，E5）——校准输出的不是绝对真值，是**区间**。方法论沿用 calibration-plan-v3 校准矩阵（变量控制/先后手平衡/样本量），锚带 CI 一并入档；
2. **采集**：固定深度档（与③联动：校准用分析档写死，不随用户深度设置漂移）、固定先手/后手各半、批跑走**长任务脱离规约**（nohup + 固定输出路径，Tina 起跑收割，禁止盯进程）；样本量按 calibration-plan-v3 §四 口径，预计 lvl3/5/7 × 双先手 × 30 局档起步；
3. **拟合与落档**：胜率→Elo 反推（logistic，CI ±带），映射曲线校准参数带版本号入档，与①的 engineVersion 过期机制同构（校准参数升级 = 旧估算标过期）；**跨版本对比语义（v0.3 补，P2-4）**：旧校准参数下的历史相对指标与新参数不可直接对比，趋势箭头跨版本须断链处理（文案层标注"校准基准已更新"或趋势重置），防用户看到"水平骤降"假象；
4. **诚信降级（先行项，不等校准完）**：校准完成前，玩家报告中 Elo 绝对值降级为相对指标（如"超过 X% 对局水平"或趋势箭头），文案改动 0.5d 内可先行——建议随 Phase 1 一起出，立刻止血虚高展示。**降级范围 = 全部 Elo 绝对值出口清单化盘点**（v0.3 补，P2-2：已知至少 AssessmentView.swift:65-70、SettingsView.swift:48，报告页/设置页/未来面全盘，防漏改降级不彻底；盘点含在 0.5d 内）；
5. **极端值排查 P2×5-7**：归本 Phase 精度域收尾项，随校准数据一并处理。

**工作量与日历（v0.3 补 P2-3）**：诚信降级 0.5d（Cody，先行）＋ 采集跑批 1-1.5d 等效（Tina 长任务）＋ 拟合落档 1d（Alex+Eric）＋ 映射实施 0.5-1d（Cody）。**日历窗口预警**：lvl3/5/7 × 双先手 × 30 局 = 180 局长任务，人日 3-4 但日历时间可能显著拉长（参考 A2 消融单批 50 局纯计算 ~21.7h）——采集分批起跑（每锚点独立批次，跑完一个拟合一个），**回退口径：样本不足或 CI 过宽 → 维持相对指标不算校准失败**，防版本窗口被采集拖死。
