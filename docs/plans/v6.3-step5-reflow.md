## 1. L5 回流规约固化（known-issues 条目 + 工单模板锚）

**规约正文**（已落档 ~/DevTeam/knowledge/known-issues.md「L5 回流规约（v6.3 收口固化）」条）：

1. **修复必带回归测试同 commit**——测试以"症状指纹"为单位锢定（复现原红的最小断言），不是顺手的正向用例。
2. **不变量声称必须带验证**——commit message / 文档里"恒为/必然/不会再现"类断言，同一交付面内必须有可执行验证（测试或对账脚本），否则视为未声称。
3. **suite 状态复位 + skip 单源**——测试写共享态必走隔离工具（withUDKey / defaults 域快照），禁裸写 UserDefaults 共享键；skip 只进单源清单（带 reason），禁散落命令行。
4. **逃逸 Bug 回流**——每例逃逸在 known-issues 落档时必须带：根因层归属 + 修复 commit + 回归测试锚；无三者之一不得关账。
5. **关账重开条款（一般惯例，G-1 首例）**——关账 ≠ 一刀死：关账条须附"重开触发指纹"（何种形态再现则自动重开并升级），与观察项处置同构（参照 P2-1 滞留角落条）。

**两案锚（正例）**：
- **PA-1**（a5d1634 + 20694ae）：C 层 depth 采集修复，同 commit 带两症状指纹回归用例（evaluate depth=0 / multiPV 三候选全 depth=0 各一），并注明覆盖面=全调用点。规约 1 的标准形态。
- **SIGILL 021128b**（7d0104d + 021128b）：根治 commit 带回归指纹（SigillIronGateRegressionTests 89 行）；Ruby 复审追加固化点——poolBase 128 避开 D5I18n 字面量带 + 「不变量声称必须带验证」教训（规约 2 的来源）。

## 3. G-1 查证单：④-5 直写 UserDefaults 读回 nil —— 关账

**定性：单次环境伪象 + 测试初版写法缺陷，非产品缺陷，不生成工单，关账。**

证据链：
1. **复现范围唯一**：仅 selcons-test2（08-28，初版直写形态、未入库）一批出现；初版代码从未 commit（首入库 1189989 已是真实 didSet 路径版本）。
2. **后续零复现**：test3 起 ≥6 批全绿（selcons-test3/5/6/7/8、formal1/3、s43-baseline-test8/**test9**）。决定性旁证：test9（r3g 基线）同期仍有跨 suite L10n 假红指纹（V60Phase1 displayName 10 红），但 ④-5 通过——说明该 nil 与 L10n 竞态不同源，且在无互斥环境下也未被再次触发。
3. **产品路径无此形态**：用户路径恒经 ThemeManager.currentTheme didSet 落盘，被 ③-4（读档态合法性）+ ④-5（写入即落盘往返）双锢定；裸写共享键只存在于测试初版，用户面不可达。
4. **机制定性（架构师层面，未做进程级隔离）**：直写-读回断言对同进程 cfprefsd 缓存竞态/批间 defaults 域干扰敏感，属测试写法脆弱面；真实路径版本（withUDKey 隔离 + didSet）从结构上消除该敏感面。

**回流动作**：
- known-issues「④-5 直写 UserDefaults 读回 nil」条改判关账（本单为锚）+ **重开条款**（Vera 附加）：若 withUDKey 模式版本再出现"直写读回 nil"形态，本条自动重开并升级为产品面排查——关账留观察钩子，与 known-issues 观察项惯例同构。
- 规约补充（并入 §1 规约 3）：测试禁裸写 UserDefaults 共享键——SelectionConsistencyTests 的 withUDKey 模式为模板。
- 进程级 defaults 隔离不做（Vera 裁）：关账标准 = 非产品缺陷 + 敏感面结构性消除，两者已满足；测试环境脆弱性一般面已由 Step 1 部分收口，残余归测试环境域，不派 Tina。
