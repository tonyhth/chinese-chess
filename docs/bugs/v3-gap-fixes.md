# v3.0 补齐任务 — 方案对照差距修复

## 背景
v3.0 方案 v6.1 审计发现 4 个关键差距，需在打包前补齐。

## 任务清单

### Bug 1: 每日残局不可玩（P0）
**现象**：`DailyChallenge.swift` 中 `puzzleId` 硬编码为 nil，每日挑战的残局模式无实际残局可玩。
**方案要求**：每天从 365 局题库中按日期哈希取 1 局。
**修复方向**：
1. 从现有 PuzzleStore 的 551 局残局库中，按日期哈希选取 1 局
2. `puzzleId` 设为选取的残局 ID
3. DailyChallengeView 中残局模式可点击进入实际残局

### Bug 2: 段位特权空壳（P1）
**现象**：方案设计了丰富的玩法特权（AI教练/引擎分析/开局树等），但这些底层功能计划在 v3.0.5，当前段位特权只有主题解锁。
**处理方向**：
- v3.0 不实现 v3.0.5 的功能，但需要在段位 UI 中**标注哪些特权"即将上线"**
- 避免用户升段后发现特权是空壳
- 连续登录奖励同理：如果奖励是"解锁新残局/主题/棋子样式"，需要实际解锁逻辑，不能只是文字

### Bug 3: 连续登录奖励无实际解锁（P1）
**现象**：DailyChallenge 的连续登录 8 阶梯（3/7/14/30/45/60/70/100天）只有文字描述，无实际解锁逻辑。
**修复方向**：
- 3天 → 解锁 1 个新残局（从题库中解锁）
- 7天 → 解锁 1 个新主题色
- 14天 → 解锁专属棋子样式
- 30天+ → 解锁对应内容
- 与 ThemeManager / PuzzleStore 对接

### Bug 4: 主题解锁不完整（P1）
**现象**：方案要求段位+成就双向关联解锁，当前只有段位关联（3个主题），无成就关联。
**修复方向**：
- 钻石成就解锁专属主题（方案中有明确对应）
- 补充专属棋子样式/棋盘纹理（如段位达到进士/翰林/国手/棋圣）

### 任务 5: Route A Spike（P0，但独立处理）
**说明**：Pikafish GPLv3 法律评估 + iOS C++ 编译 Spike 是 v3.1 的前置任务，不是 v3.0 的代码任务。但方案要求 v3.0 期间出结论。
**处理**：此任务由洪涛决策层面推进（法律评估需要外部 input），开发团队不做代码实现。需在 v3.0 发布说明中标注"Route A 可行性待评估"。

### 任务 6: Elo 外部基准验证（P0）
**说明**：代码优化已到位（搜索8项+评估深度调优），但没有外部基准验证数据。
**处理**：自对弈框架已有，可在打包前跑一轮 release build 自对弈（hard vs hard 20局），输出内部 Elo 估算。外部基准（xiangqi.com 排位赛）需洪涛人工操作。
