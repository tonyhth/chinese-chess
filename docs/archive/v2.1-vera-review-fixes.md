## P0 修复（1项）

### P0-1：iOS 缺少统计面板 + 主题选择器入口

**问题**：macOS 入口有 `showStats` 和 `showThemePicker` 按钮，iOS 入口完全没有，用户无法查看胜率统计和切换棋盘主题。

**修复方案**：

1. **ChineseChessiOSApp.swift**：在 iOS 的 toolbar 或 sheet 中增加两个入口：
   - 统计面板：sheet 弹出 `StatsPanelView`，复用现有 `StatsViewModel`
   - 主题选择器：sheet 弹出 `ThemePickerView`，复用现有 `BoardTheme`

2. **实现细节**：
   - iOS 用 `.toolbar` + `ToolbarItem` 放置图标按钮（统计用 chart.bar 图标，主题用 paintpalette 图标）
   - 点击触发 `@State var showStats = false` / `showThemePicker = false`，`.sheet()` 呈现
   - 两个 sheet 内容与 macOS 版完全复用，无需重写

3. **验证**：iOS 模拟器中确认两个入口可点击、sheet 正常弹出、数据联动正确

## P1 修复（4项）

### P1-1：TimeManager isIOS 未传入

**问题**：`AIEngine.hardSearch`/`masterSearch` 调用 `TimeManager.forDifficulty` 时未传 `isIOS`，iOS 上始终使用 macOS 时限（hard=5s, master=10s），可能导致主线程阻塞被系统 kill。

**修复方案**：

1. **AIEngine.swift**：添加平台检测属性
   ```swift
   private static var isIOS: Bool {
       #if os(iOS)
       return true
       #else
       return false
       #endif
   }
   ```

2. **调用处修改**：`hardSearch` 和 `masterSearch` 中调用 `TimeManager.forDifficulty` 时传入 `isIOS: Self.isIOS`

3. **影响范围**：仅修改 AIEngine.swift 2 处调用点，TimeManager 本身无需改动

4. **验证**：iOS 上 hard 难度 AI 思考时间应降至 3s，master 降至 6s

5. **补充（Vera 审查）**：`CheckmateSearch` 的 `timeLimitMs` 同样硬编码（hard 800ms / master 1500ms），iOS 上也有主线程阻塞风险。需同步加平台区分：
   - hard iOS→500ms，master iOS→1000ms
   - 在 `hardSearch`/`masterSearch` 中构造 `CheckmateSearch` 时，传入平台检测后的时限值

---

### P1-2：3 局残局空 solution 无降级

**问题**：`shq_042`/`shq_065`/`shq_090` 的 solution 为空数组，用户进入后无法通关，卡死。

**修复方案**：

1. **PuzzleViewModel.swift**：在 `loadPuzzle()` 或 `startPuzzle()` 中检查 solution 是否为空
   ```swift
   var isSolvable: Bool { !puzzle.solution.isEmpty }
   ```

2. **PuzzleSelectView.swift**：对空 solution 残局做 UI 降级
   - 列表项显示标记（如灰底 + "暂无解" badge）
   - 点击时弹出提示"该残局暂无解答，敬请期待"，不进入解题界面

3. **不删除数据**：保留这 3 局的 puzzle 数据，后续补 solver 后可无缝启用

4. **验证**：点击这 3 局后不会卡死，有明确提示

### P1-3：GameHistoryStore 20 局上限无导出

**问题**：对局记录上限 20 局，超出自动丢弃最旧的，且无导出/备份功能。长期用户数据丢失。

**修复方案**：

**短期（本次修复）**：
1. **上限提升**：将 `maxGames` 从 20 提升到 100，缓解数据丢失
2. **溢出提示**：当对局数 ≥ 90 时，在 `GameHistoryView` 顶部显示提示"对局记录接近上限，建议导出备份"
3. **导出功能**：
   - `GameHistoryStore` 添加 `exportAllRecords() -> String` 方法，输出 JSON 字符串
   - `GameHistoryView` 添加导出按钮，使用 SwiftUI 原生 `ShareLink`（iOS 16+/macOS 13+）
   - `ShareLink(item: jsonData)` 一行代码，无需 NSSharingServicePicker/UIActivityViewController 桥接
   - 导出格式：JSON，包含所有 GameRecord 字段
   - ⚠️ 最低部署版本需 ≥ iOS 16 / macOS 13（需确认项目配置，若低于此版本则改用 `UIActivityViewController` 条件编译方案）

**长期（可延后）**：
- 迁移到 SwiftData/CoreData 存储方案，无硬上限

4. **验证**：导出的 JSON 可被重新导入验证数据完整性

---

### P1-4：GameRecord initialFEN 始终 nil

**问题**：`buildGameRecord()` 中 `initialFEN` 传 nil，所有记录假设标准开局。从残局或自定义 FEN 开始的对局无法还原初始局面。

**修复方案**：

1. **前置依赖（Vera 审查）**：当前 `FENParser` 只有解析，没有生成方法。`Board` 无 `fenString()` 方法。需先在 `FENParser` 中补实现：
   ```swift
   static func fenString(for board: Board) -> String
   ```
   生成规则：遍历棋盘 10 行 × 9 列，按 FEN 标准输出（空位连续计数，行间 `/`，底部加 `w` 或 `b` 表示走子方）

2. **GameViewModel.swift**：`buildGameRecord()` 中正确传入当前棋局的 FEN
   ```swift
   initialFEN: FENParser.fenString(for: board)
   ```

3. **ReplayViewModel.swift**：回放时使用 `initialFEN` 初始化棋盘，而非硬编码标准开局
   ```swift
   if let initialFEN = record.initialFEN {
       board = Board(fen: initialFEN)
   } else {
       board = Board()  // 兜底：标准开局
   }
   ```

4. **数据兼容**：旧记录 `initialFEN = nil` 时 fallback 到标准开局，不影响已有数据

5. **验证**：从残局进入对局 → 保存 → 回放，初始局面正确还原

## P2 修复（5项，建议修但可延后）

### P2-1：AIDifficulty displayName 耦合

**问题**：`displayName` 扩展定义在 `GameHistoryView.swift` 而非 `Enums.swift`，耦合不合理。

**修复**：将 `AIDifficulty` 的 `displayName` 扩展从 `GameHistoryView.swift` 移到 `Enums.swift`。

---

### P2-2：文档与残局分类数据不一致

**问题**：checklist 说"传统名局 101 局 + 程序化 99 局"，实际为古谱残局 100 + 经典排局 12 = 112 传统，非古谱 88 局。

**修复**：更新 `v2.1-checklist.md` 中的分类描述，与实际 puzzles.json 数据一致：
- 传统名局：112 局（古谱残局 100 + 经典排局 12）
- 程序化残局：88 局

---

### P2-3：ICCS 格式切换需确认 RecordPanelView 实现

**问题**：`GameMove.notation` 只存中文棋谱，切换到 ICCS 格式时需要 RecordPanelView 实时转换。

**修复**：确认 `RecordPanelView` 在显示时是否根据当前设置重新生成 ICCS 记谱。如果未做，需修改：
- `RecordPanelView` 根据 `SettingsViewModel.notationFormat` 判断显示格式
- ICCS 格式时从 `move` 对象重新调用 `ICCSParser.iccsString` 生成

---

### P2-4：StatsManager 不覆盖人人对战

**问题**：`StatsManager` 只记录人机统计，不记录人人对战。

**修复**：当前只有人机模式，属于预期能力缺口，暂不修。后续如加入人人对战，在 `StatsManager` 中增加 `gameMode` 维度即可。

---

### P2-5：iOS 代码风格不一致 + PlatformExtensions 空壳

**问题**：
- iOS 入口 `gameViewModel` vs macOS 入口 `viewModel` 命名不一致
- `PlatformExtensions` 只定义了 `PlatformColor`，缺少字体/触控等适配

**修复**：
- 统一命名为 `viewModel`（或 `gameViewModel`），两端保持一致
- `PlatformExtensions` 暂保持现状，后续有实际需求再扩展，避免过度设计
