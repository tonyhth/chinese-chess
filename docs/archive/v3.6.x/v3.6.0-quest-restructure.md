> 负责人：丹妮 | 日期：2026-06-28
> 状态：待 Alex 设计 + Vera 审查
> 关联：v3.6.0-plan.md（AI 教练 + 引擎分析 + 开局树）
>
> 基于 2026-06-28 闯关系统深度分析。核心问题：现有4套系统（残局/段位/成就/每日挑战）互相割裂，没有形成"闯关→升级→解锁→再闯关"的闭环。

---

## 一、问题诊断

### 现状评分

| 系统 | 可玩性 | 核心问题 |
|------|--------|----------|
| 残局闯关 | ⭐⭐ | 551局平铺无章节，没有解锁链 |
| 段位系统 | ⭐ | 翰林以上奖励全是"即将上线"占位符 |
| 成就系统 | ⭐⭐ | 纯统计型，解锁无奖励反馈 |
| 每日挑战 | ⭐ | 10种模式只实现了3种，7种空壳 |

### 系统割裂图

```
残局闯关 ──→ 段位（只贡献"通关数"）
每日挑战 ──→ 段位（不贡献任何东西）
成就系统 ──→ 独立存在（和段位有重叠但不联动）
```

**没有形成闭环**：闯关→升级→解锁新内容→再闯关。

---

## 二、设计目标

**一句话**：让新玩家打开 App 就知道"从哪里开始，下一步干什么，为什么要继续玩"。

### 玩家旅程（目标状态）

```
首次打开 → 新手教程（5步，已有）
    ↓
第一章入门残局 → 每日残局挑战 → 获得首胜成就
    ↓
升到秀才 → 解锁翡翠绿主题 → 第二章解锁
    ↓
连续登录3天 → 残局进度×2 → 每日闪电局
    ↓
升到举人 → 解锁帝王金 → 第三章解锁
    ↓
... 胜场+残局数双线推进 ...
    ↓
升到翰林 → 解锁自由对弈残局 + 引擎分析（v3.6.0 Phase 2）
    ↓
升到国手 → 解锁 AI 教练（v3.6.0 Phase 3）
    ↓
最终目标：棋圣 + 全成就 + 全残局通关
```

## 三、Phase 分解

### Phase Q1：残局章节制（核心改动）

**改动量**：中（主要是 PuzzleSelectView + PuzzleStore + 数据层）

#### Q1.1 章节数据模型

**新增文件**：`Models/PuzzleChapter.swift`

```swift
struct PuzzleChapter: Identifiable {
    let id: String              // "ch1", "ch2"...
    let title: String           // "第一章 入门"
    let subtitle: String        // "从这里开始你的象棋之旅"
    let starRange: ClosedRange<Int>  // 1...1
    let puzzleIds: [String]     // 该章节包含的残局 ID
    let unlockRequirement: ChapterUnlock  // 解锁条件
    let unlockReward: ChapterReward?      // 通关奖励
}

enum ChapterUnlock {
    case none                          // 无前置（第一章）
    case completeChapter(chId: String, count: Int)  // 通关前一章N局
    case rank(Rank)                    // 达到段位
}

struct ChapterReward {
    let description: String
    let type: RewardType
}

enum RewardType {
    case unlockChapter(chId: String)
    case theme(BoardTheme)
    case title(String)                 // 称号
    case feature(String)               // 功能解锁
}
```

#### Q1.2 章节划分（551局 → 7章）

| 章节 | 标题 | 难度 | 局数 | 解锁条件 |
|------|------|------|------|----------|
| 第一章 | 入门 | 1★ | 50 | 无 |
| 第二章 | 初级 | 1-2★ | 50 | 通关第一章10局 |
| 第三章 | 进阶 | 2-3★ | 80 | 通关第二章20局 |
| 第四章 | 中级 | 3★ | 100 | 通关第三章30局 |
| 第五章 | 高级 | 3-4★ | 100 | 通关第四章40局 |
| 第六章 | 大师 | 4-5★ | 100 | 通关第五章50局 |
| 第七章 | 挑战 | 5★ + freePlay | 71 | 通关第六章40局 + 段位≥进士 |

**设计原则**：
- 前3章面向新手，每章局数少、推进快（成就感频繁）
- 后4章面向进阶玩家，局数多、难度陡峭
- 第七章包含全部17个 freePlay 残局 + 最高难度 guided 残局

#### Q1.3 章节选择 UI

**修改文件**：`Views/PuzzleSelectView.swift`

改造现有平铺列表为「章节选择 → 残局列表」两级结构：

**第一级**：章节卡片列表（横向滚动或网格）
- 每章显示：标题 + 进度条（已通关/总数）+ 锁/解锁状态
- 锁定章节灰色 + 锁图标 + 解锁条件提示
- 已解锁章节正常色 + 通关进度

**第二级**：进入章节后的残局列表（现有 PuzzleSelectView 逻辑复用）
- 保留分类筛选、难度筛选、搜索功能
- 增加：章节内进度条 + "完成本章"奖励预览

#### Q1.4 兼容老存档

- 章节制是 UI 层重组，不改 puzzles.json 数据结构
- 已通关的残局进度保留，自动映射到对应章节
- 章程解锁状态通过 PuzzleProgress 推导（不需要新存档字段）

**工期估算**：3-4 天

#### Q2.2 段位解锁实现

**修改文件**：`Models/PlayerProfile.swift`

新增段位解锁检查方法：
```swift
extension PlayerProfile {
    /// 检查某功能是否已解锁（基于段位）
    func isFeatureUnlocked(_ feature: UnlockedFeature) -> Bool {
        switch feature {
        case .chapter2Early: return rank >= .scholar
        case .freePlayPuzzles: return rank >= .hanlin || /* 或第七章已解锁 */
        case .engineAnalysis: return rank >= .hanlin
        case .aiCoach: return rank >= .master
        case .openingTreeFavorite: return rank >= .sage
        }
    }
}

enum UnlockedFeature {
    case chapter2Early
    case freePlayPuzzles
    case engineAnalysis
    case aiCoach
    case openingTreeFavorite
}
```

### Phase Q3：成就系统激活

**改动量**：小

#### Q3.1 成就→段位联动

成就解锁不再只是打✓，部分成就直接贡献段位升级：

- "tutorial_done" → 等价1个胜场（首次启动就有，给用户正反馈）
- "first_puzzle" → 等价1个残局通关
- 特殊成就（如"perfect_game"）→ 额外统计加成

**实现**：在 `AchievementManager.unlock()` 中增加 `PlayerProfileStore.update` 联动。

#### Q3.2 新增行为型成就（替换部分纯统计型）

从现有34个成就中替换8个为更有趣的"行为型"成就：

| 移除 | 替换为 | 条件 |
|------|--------|------|
| play_red | 马后炮 | 用马后炮将杀赢1局 |
| play_black | 双车错 | 用双车错杀法赢1局 |
| draw_game | 十步杀 | 10步内将杀AI |
| use_hint | 无悔一局 | 不悔棋赢一局（中等以上） |
| win_streak_3 | 连将三步 | 连续3步将军获胜 |
| quick_win | 闪电战 | 5分钟内赢一局（棋钟计时） |
| comeback_win | 逆转王 | 兵力劣势500+时翻盘获胜 |
| perfect_game | 完美对局 | 全程走法评级≥good（需引擎分析） |

**注意**：移除成就时检查已解锁的用户，替换后保留已解锁状态（不回收）。

#### Q3.3 成就解锁奖励

- 铜牌成就：+10 经验值（加速段位升级，如有经验系统）
- 银牌成就：解锁1个额外提示次数/日
- 金牌成就：解锁1个 3★ 残局的提前访问权
- 钻石成就：解锁专属棋子样式
- 隐藏成就：解锁特殊效果

**工期估算**：2-3 天

### Phase Q4：每日挑战做实

**改动量**：中（3种模式的实际实现）

#### Q4.1 三种核心模式实现

从10种模式中选3种最有价值且实现成本合理的：

**模式1：每日残局（已有，优化入口）**
- 现状：跳到残局列表让用户自己选 ❌
- 改为：直接打开今日残局的 PuzzlePlayView，一键开始 ✅
- 增加：完成后记录评分（星级 + 用时），加入排行榜（本地）

**模式2：闪电局（新增）**
- 利用 v3.5.0 Phase 2 的棋钟基础设施
- 双方各5分钟倒计时，超时判负
- 入口：每日挑战页 → "今日闪电局" → 直接开局
- AI 难度 = 今日推荐难度

**模式3：大师挑战（新增）**
- 强制 master 难度的对弈
- 与普通对弈的区别：入口独立 + 输了不掉胜场统计（鼓励尝试）
- 连续3天完成 → 成就"勇者"

#### Q4.2 每日挑战奖励调整

连续登录奖励表更新（去掉和段位重复的主题奖励）：

| 天数 | 现有奖励 | 新奖励 |
|------|----------|--------|

| 7天 | 翡翠绿主题（和秀才重复） | → 额外提示次数×3/天 |
| 14天 | 专属棋子样式 | → ✅ 保留（实际实现样式） |
| 30天 | 帝王金（和举人重复） | → 闪电局时间奖励+1分钟 |

| 100天 | 棋圣专属主题（无实际内容） | → ✅ 保留 + 自定义棋盘配色 |

#### Q4.3 其余7种模式

## 七、风险

| 风险 | 评估 | 应对 |
|------|------|------|
| 章节划分不合理导致551局分布不均 | 低 | 已按难度统计验证（110/110/110/110/111），分布均匀 |
| 老用户存档兼容 | 中 | 章节是 UI 层逻辑，不改存档结构；进度通过 PuzzleProgress 推导 |
| 成就替换导致数据不一致 | 中 | 只替换触发条件，ID 保持不变或做 migration |
| 每日挑战模式缩小到3种用户感知退化 | 低 | UI 上10种保留展示，3种可玩标记"NEW"，7种标"敬请期待" |
| 金币经济系统工作量过大 | 中 | Q5 设为可选，不影响 Q1-Q4 闭环 |
| 段位门禁过于严格影响体验 | 中 | 关键功能（分析/教练）可通过连续登录奖励绕过段位限制 |
