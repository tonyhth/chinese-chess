## 具体实施内容

### 9.1 AI 教练模式

**工作流程**：
1. AI 根据玩家段位自动调整棋力（比玩家略强一级）
2. 关键局面（评估分落差 ≥ 200 分）时暂停，弹出提示
3. 玩家选择：提示 / 详解 / 跳过
4. 对局结束生成"复盘卡片"

**讲解生成方案（8 类场景模板）**：

| 场景 | 触发条件 | 讲解模板 |
|------|---------|---------|
| 送子 | 评估落差 ≥ 300，丢子 | "这步会丢掉{piece}，{better}可以保住它" |
| 漏杀 | 对方有杀棋未防 | "对方有{N}步杀，{better}可以防守" |
| 错失杀机 | 玩家有杀棋未走 | "这里可以{N}步将杀，{better}是关键" |
| 将军机会 | 有将军未走 | "可以将军！{better}先手占优" |
| 吃子机会 | 有安全吃子未走 | "可以安全吃掉{piece}，{better}" |
| 兵力展开 | 走法未展开子力 | "此时展开子力更重要，{better}" |
| 防守优先 | 应防守时进攻 | "当前应先防守，{better}更稳妥" |
| 控制中线 | 中线控制更优 | "控制中线是关键，{better}" |

**未匹配 fallback**："这步有更好的选择，{better_move}评估高出{delta}分"

**复盘卡片内容**：
- 走法统计：X 步好棋，Y 步疑问手
- 最大失误：第 N 步，应该走...
- 棋力评分：★☆☆☆☆ ~ ★★★★★
- 提升建议："你的中局防守偏弱，推荐练习 X 类残局"

**技术实现**：
- 利用引擎为每步走法评分
- "教练难度" = 玩家当前段位对应难度 + 1
- 关键局面检测：评估分数落差 ≥ 200 分
- 讲解模板渲染：用走法信息填充模板变量

### 9.2 引擎分析（复盘模式）

**走法质量 6 级分级**：

| 等级 | 名称 | 判定条件 |
|------|------|---------|
| 5 | 精妙 | 与最佳走法评估差 ≤ 10，或找到独一妙手 |
| 4 | 好棋 | 与最佳走法评估差 ≤ 50 |
| 3 | 正常 | 与最佳走法评估差 ≤ 100 |
| 2 | 疑问手 | 与最佳走法评估差 ≤ 300 |
| 1 | 漏着 | 与最佳走法评估差 ≤ 700 |
| 0 | 败着 | 与最佳走法评估差 > 700 |

**分析 UI**：
- 棋盘上标注每步走法颜色（绿/黄/红）
- 侧边栏：走法列表 + 质量标签
- 点击某步 → 棋盘回放 + 显示最佳走法对比
- 分析曲线：评估分数随步数变化折线图

**解锁条件**：秀才以上可用基础分析，进士以上可用专家分析（多候选走法）。

### 9.3 开局树探索

**功能**：
- 交互式开局树可视化
- 每步显示：走法名称、胜率统计、AI 推荐度
- 对方常见应手及后续变化
- 收藏开局线路

**数据源**：开局库 + 开局名称映射表（Phase 7/8 产出）。

**UI 设计**：
- 树形结构展开/折叠
- 点击节点 → 棋盘演示
- 收藏按钮 → 保存到 `PlayerProfile.openingBookmarks`

**解锁条件**：秀才以上可用。

```
        ├── 输入 ← Phase 7/8（开局库扩展 + 名称映射）

```

**并行标记**：
- Phase 9 的三个功能（教练/分析/开局树）内部可部分并行
- AI 教练依赖引擎分析能力（`evaluatePosition` / `analyzeMove`），所以 PositionAnalyzer 需先完成
- 开局树与教练/分析完全独立，可并行
