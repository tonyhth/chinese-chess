## 具体实施内容

### 4.1 技术路径调研

**调研项 A：NNUE 架构理解**
- NNUE（Efficiently Updatable Neural Networks）原理研究
- 国际象棋 Stockfish NNUE 架构分析：halfKP 特征集、增量更新策略
- 将棋（Shogi）NNUE 适配案例
- 象棋特有因素：棋盘 9×10（vs 国际象棋 8×8）、棋子种类差异、规则差异

**调研项 B：Pikafish NNUE 架构分析**
- Pikafish 使用的 halfKP-xiangqi 特征集：226,800 维输入
- Pikafish NNUE 模型结构与推理流程
- 推理性能基准（CPU 推理速度参考值）
- 模型文件大小（~30MB）与加载时间

**调研项 C：训练数据生成**
- 用 Pikafish 自对弈生成数据的可行性（使用 ≠ 分发，不违反 GPL）
- 数据量估算：200-500 万局，8 核并行 7-10 天
- 数据格式设计：FEN + best move + evaluation score

**调研项 D：训练框架评估**
- nnue-pytorch 适配象棋的可行性
- GPU 需求：RTX 3090/4090 或云 GPU（AWS/GCP）
- 训练时间估算：2-4 天/轮，3-5 轮迭代
- 成本估算：云 GPU 按需费用

### 4.2 推理引擎方案评估

**Clean-room 实现方案**（法律合规关键）：
- 仅根据 NNUE 论文 + 公开数学描述编写推理代码
- **不参考** Pikafish/Stockfish 的 GPL 源码
- C++ 实现 → C header 接口 → Swift 桥接
- 推理性能目标：移动端 < 1ms/position

**增量更新策略评估**：
- copy-make accumulator：每次走子后全量重算（简单但慢）
- 增量更新：只更新变化的特征（快但复杂，易出 bug）
- 权衡：移动端推荐 copy-make（算力有限但正确性要求高）

### 4.3 特征集设计

**halfKP-xiangqi 特征集**：
- 输入维度：226,800（参考 Pikafish）
- 拆解：每个己方棋子 × 每个对方棋子的 king-relation 特征
- 需要验证：象棋棋盘 9×10 是否影响特征设计（vs 国际象棋 8×8）

**特征工程研究**：
- 象棋特有特征：河界、九宫、士/象的固定线路
- 是否需要扩展特征集以覆盖象棋独特规则

### 4.4 法律合规分析

- 训练数据来源：用 Pikafish 自对弈是否合规？（使用 ≠ 分发）
- 推理代码：clean-room 实现的法律保障程度
- 训练框架：nnue-pytorch 的许可证
- 与 GPLv3 的隔离策略

### 4.5 可行性报告

**输出物**：`docs/nnue-feasibility-report.md`

**报告结构**：
1. 技术可行性评估（架构、特征集、推理方案）
2. 资源需求评估（GPU、人力、时间）
3. 法律合规评估
4. 成本估算
5. Elo 预估（v1: 3000-3300, v2: 3300-3500, v3+: 3500+）
6. 启动条件 checklist
7. 推荐启动时机
