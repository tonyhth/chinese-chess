## 可并行性总结

### 可完全并行（不同技术栈/代码区域）

| 组合 | 说明 |
|------|------|
| Phase 1/2/3 ↔ Phase 4 | AI Swift 代码 ↔ NNUE 纯调研 |
| Phase 1/2/3 ↔ Phase 5/6 | AI 引擎代码 ↔ UI/可玩性代码 |
| Phase 4 ↔ Phase 5/6 | NNUE 调研 ↔ 可玩性开发 |
| Phase 9 内部：开局树 ↔ AI 教练/分析 | 独立功能模块 |

### 串行依赖（必须按序）

| 顺序 | 原因 |
|------|------|
| Phase 1 → Phase 2 | 搜索升级需要 Elo 基线做对比 |
| Phase 2 → Phase 3 | 评估调优需在新搜索框架上验证 |
| Phase 5 → Phase 6 | 成就条件依赖段位枚举 |
| Phase 6 → Phase 7 | 每日挑战高级模式受段位解锁 |
| Phase 6+7 → Phase 8 | 主题经济/迁移依赖段位+成就+残局数据 |
| v3.0 交付 → Phase 9/10 | v3.0.5/v3.1 是后续版本 |

### 有条件并行

| 组合 | 条件 |
|------|------|
| Phase 7（残局库）↔ Phase 3（评估调优） | 残局库扩展不修改 AI 搜索逻辑，可并行 |
| Phase 8（主题设计）↔ Phase 7 | 主题图标设计可与功能开发并行 |

## 风险提示

| 风险 | 影响 Phase | 缓解 |
|------|-----------|------|
| Route A Spike 法律不合规 | Phase 10 | 转兜底方案（Phase 3 延伸 + Phase 11 远期） |
| Route A Spike 技术不可行 | Phase 10 | 同上 |
| 评估调优 Elo 不达标 | Phase 3 | 接受 ~2200 作为 v3.0 目标，3500+ 推迟 |
| 可玩性排期延误 | Phase 5-8 | 降低非核心功能优先级（如开局库可推迟） |
| NNUE 条件不具备 | Phase 11 | Route A 优先，NNUE 无限推迟 |
