## 附：Alex 预审发现（供执行人参考）

### ⚠️ R5: deinit 中的 actor 属性访问（P0）

`EmbeddedPikafishEngine.swift:56`:
```swift
deinit {
    if isReady {
        pikafish_quit()
    }
}
```

Swift actor 的 deinit 在非 isolated 上下文执行。直接访问 `isReady`（isolated 属性）在 Swift 5.x 中可能触发运行时警告或未定义行为。

**建议**：Vera 确认 Swift 版本行为；如果 5.9+ 允许 deinit 读取 isolated 存储属性，标记为安全；否则建议改为 `nonisolated(unsafe) var isReady` 或在 shutdown 前显式清理。

### ⚠️ R3: actor + DispatchQueue 混用（P1）

`bestMove` 在 actor 方法内通过 `DispatchQueue.global().async` 执行 C 调用，然后 `withCheckedContinuation` resume。这本身是安全的，但：
- `pikafish_stop()` 是 `nonisolated`，可以在 bestMove 执行期间从任意线程调用
- `shutdown()` 和 `deinit` 都可以触发 `pikafish_quit()`
- 如果 quit 在 bestMove 执行期间被调用，C 侧内部状态可能不一致

**建议**：Ruby 确认 pikafish C API 的 `pikafish_quit()` + 并发 `pikafish_best_move()` 的安全性。

### ⚠️ R6: 国际化覆盖极低（P1）

`.localized` 仅 1 处使用，`String(localized:)` 0 处。但 xcstrings 文件 68KB 存在。

**可能原因**：项目使用其他国际化方式（如 SwiftUI Text 自动 localization）。需要 Ruby 确认国际化机制，不一定是问题。
