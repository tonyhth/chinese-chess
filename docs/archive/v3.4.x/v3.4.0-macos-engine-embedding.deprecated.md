# v3.4.0 macOS 静态库嵌入方案

> 目标：macOS 也嵌入 pikafish 静态库，与 iOS 共用同一套引擎集成层。
>
> **版本号**：macOS 嵌入 + iOS 嵌入统一在 v3.4.0 完成。

## 背景

### 当前状态

| 平台 | 当前方案 | 问题 |
|------|----------|------|
| macOS | 外部进程 + stdin/stdout 管道 | 用户需单独下载配置 pikafish，体验差 |
| iOS | 静态库嵌入（Phase 2 执行中） | 无（正在实施） |

### 目标

macOS 也改为静态库嵌入，**与 iOS 共用同一套 C API + ObjC Wrapper + Swift Actor**，只是编译目标不同：

| 平台 | 编译架构 | NNUE |
|------|----------|------|
| iOS device | arm64 | 嵌入（70MB 大网络） |
| iOS simulator | arm64 / x86_64 | 嵌入 |
| macOS | x86_64 / arm64 | 嵌入（70MB 大网络） |

### 收益

1. **用户体验**：macOS 用户不再需要下载配置 pikafish，开箱即用
2. **架构统一**：iOS/macOS 共用 C API + ObjC Wrapper + Swift Actor，减少维护成本
3. **性能**：进程内调用比管道通信更快（无序列化/反序列化开销）
4. **稳定性**：无进程管理问题（启动失败、僵尸进程、管道断裂等）

---

## 方案设计

### 核心思路：统一 EmbeddedPikafishEngine

**iOS 和 macOS 共用同一个 `EmbeddedPikafishEngine` actor**，只是编译条件不同：

```swift
// 之前：#if os(iOS)
// 之后：iOS + macOS 共用（删除 #if os(iOS) 条件编译）
actor EmbeddedPikafishEngine: ChessEngine {
    // ... 实现完全一致
}
```

**共用层次**：

| 层次 | 共用方式 | 说明 |
|------|----------|------|
| C API（pikafish_api.h/cpp） | 完全共用 | 同一套源文件 |
| ObjC Wrapper（PikafishEngine.h/m） | 完全共用 | 同一套源文件 |
| Swift Actor（EmbeddedPikafishEngine.swift） | 完全共用 | 删除 `#if os(iOS)` 条件 |
| Xcode target | 共用 target + 多编译目标 | 一个 target 支持 iOS + macOS |

### 架构对比

```
当前 macOS 架构：
  EngineRouter → ExternalEngineManager → Process + Pipe + UCITransceiver → pikafish 进程

目标架构（iOS/macOS 统一）：
  EngineRouter → EmbeddedPikafishEngine → ObjC Wrapper → C API → pikafish 静态库
```

## 1. 编译方案

### 1.1 Xcode Target 配置

macOS 静态库编译与 iOS 共用同一个 Pikafish Xcode target：

| 编译目标 | 架构 | 平台 |
|----------|------|------|
| iOS device | arm64 | iphoneos |
| iOS simulator | arm64 / x86_64 | iphonesimulator |
| macOS | x86_64 / arm64 | macosx |

> macOS 支持 x86_64（Intel Mac）和 arm64（Apple Silicon Mac）。Xcode 自动处理 universal binary。

### 1.2 NNUE 嵌入

macOS 和 iOS 一样使用大网络（70MB）嵌入：
- 编译参数：`-DNNUE_EMBEDDING_ON`
- 嵌入到静态库中，运行时无需额外文件

### 1.3 App 大小影响

| 平台 | 当前大小 | 增量 | 新大小 |
|------|----------|------|--------|
| iOS | ~35MB | +70MB（NNUE） | ~105MB |
| macOS | ~15MB | +70MB（NNUE） | ~85MB |

> macOS App 大小 ~85MB 可接受（macOS App 常见 100MB+）。

## 2. 引擎集成层共用

### 2.1 C API（完全共用）

`pikafish_api.h` / `pikafish_api.cpp` 不需要任何平台条件编译。C API 是纯 C/C++ 代码，与平台无关。

### 2.2 ObjC Wrapper（完全共用）

`PikafishEngine.h` / `PikafishEngine.m` 不需要平台条件编译。Objective-C 在 iOS 和 macOS 上都能编译。

> **注意**：macOS 支持 Objective-C 运行时，ObjC 代码可以直接编译。不需要改为 Swift。

### 2.3 Swift Actor（删除条件编译）

当前 iOS 方案中 `EmbeddedPikafishEngine.swift` 用 `#if os(iOS)` 包裹。macOS 嵌入后，删除条件编译，两个平台共用：

```swift
// 之前
#if os(iOS)
actor EmbeddedPikafishEngine: ChessEngine { ... }
#endif

// 之后（删除 #if os(iOS)）
actor EmbeddedPikafishEngine: ChessEngine { ... }
```

### 2.4 内存控制（平台差异）

iOS 和 macOS 内存策略不同：

```swift
private func configureTTSize() {
    let physicalMemory = ProcessInfo.processInfo.physicalMemory
    let ttSizeMB: Int

    #if os(iOS)
    // iOS：保守策略
    if physicalMemory < 2_000_000_000 {
        ttSizeMB = 16
    } else if physicalMemory >= 4_000_000_000 {
        ttSizeMB = 64
    } else {
        ttSizeMB = 32
    }
    #else
    // macOS：宽松策略（通常 >= 8GB RAM）
    ttSizeMB = 256
    #endif

    pikafish_set_option("Hash", String(ttSizeMB))
}
```

## 3. 现有外部进程方案的迁移策略

### 3.1 推荐：完全替换（不保留外部进程选项）

**理由**：
1. **用户体验**：嵌入方案开箱即用，外部进程方案需要用户下载配置
2. **维护成本**：保留两套方案意味着维护 ExternalEngineManager + UCITransceiver + Pipe + Process 全部代码
3. **稳定性**：进程管理问题（启动失败、僵尸进程、管道断裂）消失
4. **架构简化**：删除 ExternalEngineManager、UCITransceiver、MockUCIEngine 等文件

**删除的文件**：
- `ExternalEngineManager.swift`（242 行）
- `UCITransceiver.swift`（约 300 行）
- `MockUCIEngine.swift`（约 80 行）

**删除的配置**：
- `ExternalEngineConfig` 中的 `executablePath`、`arguments`、`options`、`useInProcessMock`
- `EngineConfigStore` 中的外部引擎配置列表管理（`engines`、`addEngine`、`removeEngine`）

### 3.2 备选：保留外部进程作为高级选项

如果需要保留外部进程作为高级选项（供高级用户使用自定义引擎）：
- 嵌入引擎作为默认选项
- 外部进程引擎作为可选选项（在设置中开启）
- 保留 ExternalEngineManager + UCITransceiver
- EngineRouter 支持三种模式：内置 → 嵌入 → 外部进程

**不推荐**：增加维护成本和复杂度，收益不大。

### 3.3 迁移影响

| 功能 | 当前实现 | 迁移后 |
|------|----------|--------|
| 引擎切换 | EngineRouter macOS 分支启动 Process | EngineRouter 调用 EmbeddedPikafishEngine |
| 引擎配置 | EngineConfigStore 管理 ExternalEngineConfig | 简化：只保留 bool（useEmbeddedEngine） |
| 引擎启动 | ExternalEngineManager.start() → Process.launch() | EmbeddedPikafishEngine.start() → pikafish_init() |
| 走棋 | stdin "position fen ..." + "go depth N" → stdout "bestmove" | pikafish_best_move(fen, moves, depth, ...) |
| 停止搜索 | stdin "stop" → stdout "bestmove" | pikafish_stop() |
| 新局 | stdin "ucinewgame" | pikafish_new_game() |
| 引擎信息 | 解析 stdout "id name/version" | C API 暴露 pikafish_get_info()（可选） |
| info 回调 | 解析 stdout "info depth/score/nps/pv" | C API 暴露 info callback（可选，后续实现） |

### 3.4 EngineRouter 改动

macOS 分支与 iOS 统一：

```swift
// 之前：macOS 和 iOS 分开处理
#if os(macOS)
private var externalEngine: (any ChessEngine)?
private var currentConfigId: UUID?
#endif
#if os(iOS)
private var externalEngine: EmbeddedPikafishEngine?
#endif

// 之后：统一（删除 #if os）
private var externalEngine: EmbeddedPikafishEngine?

@MainActor
func activeEngine() -> any ChessEngine {
    if let ext = externalEngine {
        return ext
    }
    return nativeEngine
}

@MainActor
func switchEngineIfNeeded() async -> any ChessEngine {
    let store = EngineConfigStore.shared
    if store.useEmbeddedEngine {
        if externalEngine == nil {
            externalEngine = EmbeddedPikafishEngine()
            try? await externalEngine!.start()
        }
        return externalEngine ?? nativeEngine
    } else {
        if let ext = externalEngine {
            await ext.shutdown()
            externalEngine = nil
        }
        return nativeEngine
    }
}
```

### 3.5 EngineConfigStore 简化

删除外部引擎配置管理，两个平台统一：

```swift
// 保留的属性
var useEmbeddedEngine: Bool { get/set }  // 是否使用嵌入引擎

// 删除的属性（macOS 专属）
// var engines: [ExternalEngineConfig]
// var selectedEngineId: UUID?
// var pendingEngineId: UUID?
// var pendingNative: Bool
// var wantsExternalEngine: Bool
// var hasPendingSwitch: Bool
```

> **注意**：删除外部引擎配置后，ToolbarView 的引擎设置面板需要简化（删除引擎列表 UI）。

## 4. info 回调处理

### 问题

当前 macOS 外部进程方案通过 UCITransceiver 解析 stdout 的 `info` 行（depth、score、nps、pv），实时显示搜索信息。

嵌入方案不走 stdout，需要替代方案。

### 方案

**Phase 1（v3.4.0）**：不实现 info 回调

- 嵌入引擎不提供实时搜索信息
- UI 只显示"思考中..."状态
- 走棋完成后直接显示结果

**Phase 2（后续版本）**：增加 info callback

- C API 增加回调注册函数：`pikafish_set_info_callback(void (*callback)(const char* info_line))`
- ObjC Wrapper 接收回调，通过 delegate 通知 Swift
- Swift Actor 将 info 转发给 UI

**建议**：v3.4.0 先不实现 info 回调，确保核心功能稳定。info 回调作为后续增强。

## 5. 引擎自报信息

### 问题

当前 macOS 外部进程方案通过 UCI `id name/version` 获取引擎自报的名称和版本。

嵌入方案需要在 `pikafish_init()` 后获取引擎信息。

### 方案

C API 增加信息获取函数：

```cpp
// pikafish_api.h
const char* pikafish_get_name(void);     // 如 "Pikafish"
const char* pikafish_get_version(void);  // 如 "2026.01.31"
```

ObjC Wrapper：
```objc
- (NSString *)engineName;
- (NSString *)engineVersion;
```

Swift Actor：
```swift
nonisolated var displayName: String {
    // 同步获取（pikafish_get_name 是纯读取，线程安全）
    // 或在 init 时缓存
}
```

## 6. 难度映射

macOS 和 iOS 共用难度映射（depth 策略）：

```swift
private func mapDifficultyToDepth(_ difficulty: AIDifficulty) -> Int {
    switch difficulty {
    case .beginner: return 2
    case .easy: return 5
    case .medium: return 10
    case .hard: return 18
    case .master: return 24
    }
}
```

> macOS 内存更充裕（TT size 256MB），搜索深度可以更高。但 depth 映射保持一致，避免平台差异导致走棋风格不同。
