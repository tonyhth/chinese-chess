### 目标

克隆 pikafish 源码，新增 C API 文件，验证源码可编译。**不预编译静态库**，由 Phase 2 的 Xcode target 处理编译。

### 任务清单

| # | 任务 | 文件 | 验证命令 |
|---|------|------|----------|
| 1.1 | 克隆 pikafish 源码 | 外部目录（如 `~/DevTeam/pikafish-src`） | `git clone https://github.com/official-pikafish/Pikafish.git` |
| 1.2 | 新增 C API 头文件 | `src/pikafish_api.h` | 检查文件存在 |
| 1.3 | 新增 C API 实现 | `src/pikafish_api.cpp` | 检查文件存在 |
| 1.4 | 验证源码可编译 | 临时 Makefile 或手动编译检查 | `g++ -c -std=c++17 -DNNUE_EMBEDDING_OFF src/*.cpp` 无报错 |

> **注意**：不生成静态库（删除原计划的 1.5-1.7）。Xcode target 在 Phase 2 处理编译和架构适配。

### C API 头文件内容

```cpp
// pikafish/src/pikafish_api.h
#ifndef PIKAFISH_API_H
#define PIKAFISH_API_H

#ifdef __cplusplus
extern "C" {
#endif

/// 初始化引擎（加载 NNUE，设置默认参数）
void pikafish_init(void);

/// 计算最佳走法（同步阻塞，调用者需在后台线程调用）
/// - Parameters:
///   - fen: 局面 FEN
///   - moves: UCI 走法历史（空格分隔）
///   - depth: 搜索深度（0 表示不限）
///   - time_ms: 时间限制（毫秒，0 表示不限）
///   - buffer: 调用者提供的输出缓冲区
///   - buffer_size: 缓冲区大小（建议 >= 16）
/// - Returns: 0 成功，-1 失败
int pikafish_best_move(const char* fen, const char* moves,
                       int depth, int time_ms,
                       char* buffer, int buffer_size);

/// 停止当前搜索（设置 volatile flag，线程安全）
void pikafish_stop(void);

/// 通知引擎新对局
void pikafish_new_game(void);

/// 释放引擎资源
void pikafish_quit(void);

/// 设置引擎选项（如 Hash, Threads）
void pikafish_set_option(const char* name, const char* value);

#ifdef __cplusplus
}
#endif

#endif // PIKAFISH_API_H
```

### 验证标准

- ✅ 源码编译检查通过（无报错）
- ✅ `pikafish_api.h` / `pikafish_api.cpp` 文件存在
- ✅ 文件内容符合 C API 规范（extern "C" 声明、buffer 参数）

### 风险点

- **C++ 编译错误**：pikafish 源码可能与 Xcode 编译器版本不兼容。回退：检查 Xcode C++ 编译器版本，必要时调整编译参数。
- **NNUE 文件缺失**：大网络文件可能不在源码包中。回退：从 pikafish 官网下载完整包。

### 回退方案

如果 Phase 1 遇到阻塞问题，切换到方案 B（使用 StockfishEmbedded 模板，替换源码为 pikafish）。

### Xcode 编译参数

| 参数 | 值 |
|------|---|
| C++ Language Dialect | `c++17` |
| Enable Bitcode | No（iOS 不强制） |
| Other C++ Flags | `-DNNUE_EMBEDDING_ON -O3` |
| Architectures | `arm64`（iOS device） + `x86_64`（iOS simulator） |
| Header Search Paths | `$(SRCROOT)/Pikafish/src` |

### NNUE 大网络嵌入

pikafish 的 NNUE 网络文件（约 70MB）需要嵌入静态库：

1. **方式**：编译时通过 `-DNNUE_EMBEDDING_ON` 自动嵌入（Stockfish/pikafish 默认行为）
2. **验证**：App 启动后调用 `pikafish_init()`，检查日志无 "failed to load NNUE" 错误

### 验证标准

- ✅ Xcode 编译通过（无 error）
- ✅ 生成的静态库符号表包含 `pikafish_init` 等函数
- ✅ App 运行时 `pikafish_init()` 成功（无崩溃）
- ✅ App 包大小增加约 70MB（NNUE 嵌入）

### 风险点

- **NNUE 嵌入超出编译限制**：70MB 文件可能超出编译器处理能力。回退：改为运行时加载（将 .nnue 文件放入 App bundle）。
- **链接冲突**：pikafish 的符号可能与 App 其他 C++ 代码冲突。回退：使用 namespace 包装。

### 回退方案

如果 NNUE 嵌入失败，改为运行时加载：
1. 将 `*.nnue` 文件放入 App bundle（Copy Files Build Phase）
2. `pikafish_init()` 时从 bundle 路径加载
3. 需要 `pikafish_set_option("EvalFile", path)` API

### 文件内容（要点）

```swift
#if os(iOS)

import Foundation

actor EmbeddedPikafishEngine: ChessEngine {
    nonisolated let displayName: String = "Pikafish"
    nonisolated let engineType: EngineType = .external
    private(set) var isReady = false
    
    private let objEngine: PikafishEngine
    
    init() {
        self.objEngine = PikafishEngine()
    }
    
    func start() async throws {
        try await withCheckedThrowingContinuation { continuation in
            objEngine.startWithCompletion { success, error in
                if success {
                    continuation.resume()
                } else {
                    continuation.resume(throwing: error ?? EngineError.startFailed)
                }
            }
        }
        configureTTSize()  // 调用时机：pikafish_init() 完成后即可调用（UCI setoption 不依赖 isready）
        isReady = true
    }
    
    // ... 其他方法
}

#endif
```

### 验证标准

- ✅ iOS target 编译通过
- ✅ macOS target 编译通过（文件不参与）
- ✅ `EmbeddedPikafishEngine` 实现 `ChessEngine` 协议所有方法

### 风险点

- **Actor 与 Objective-C 交互问题**：Objective-C 对象在 actor 中可能需要特殊处理。解决：`objEngine` 作为私有属性，所有调用在 actor 方法内部。
