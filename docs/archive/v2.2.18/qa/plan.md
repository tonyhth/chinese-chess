# 中国象棋 v2.1.2 商业化交付全面审查方案

> 架构师：Alex·亚历 | 审查标准：App Store 上架

## 一、审查框架

### 审查维度与权重

| 维度 | 权重 | 说明 |
|------|------|------|
| 页面布局 | 30% | 棋盘定位、各页面美观度、窗口自适应、平台差异 |
| 操作易用性 | 35% | 交互直觉、状态反馈、错误提示、快捷键 |
| 程序逻辑 | 35% | 走棋规则、AI 行为、残局数据、状态管理、边界条件 |

### 问题分级标准

| 级别 | 定义 | 处理要求 |
|------|------|----------|
| **P0** | 商业化阻塞：App Store 必拒或必差评 | 必须修复，本轮内完成 |
| **P1** | 严重影响体验：用户高频遇到且明显不适 | 必须修复，可跨轮但不超过 2 轮 |
| **P2** | 轻微影响：低频或仅审美层面 | 自行判断，记录但不阻塞发布 |

### 审查轮次

- **Round 1**：布局类问题（棋盘偏移、各页面布局、窗口自适应）
- **Round 2**：操作易用性（交互、反馈、提示、快捷键）
- **Round 3**：程序逻辑（走棋规则、AI、残局、状态管理）
- **Round 4**：复查修复 + 遗漏扫描
- 如有 P0 未清零，追加轮次

### 交付物

每轮输出 `docs/qa-audit-round-N.md`，包含：
1. 审查范围
2. 问题清单（编号、级别、描述、影响、修复建议）
3. 统计摘要（P0/P1/P2 数量）
4. 下一轮计划

最终汇总 `docs/qa-audit-summary.md`。

## 二、审查方法

### 布局审查
- 逐页面检查：主界面、残局选择、回放、设置、统计、历史、主题选择
- 检查 GeometryReader / frame / padding / position 的计算逻辑
- 检查 macOS vs iOS 条件编译分支
- 检查窗口缩放时的自适应行为

### 易用性审查
- 操作流程走查：选子→走子→AI应答→悔棋→新局
- 状态反馈完整性：选中、合法走法、将军、将死、轮次
- 错误边界：非法操作、极端窗口、快速连点
- 键盘快捷键覆盖度

### 逻辑审查
- MoveValidator 逐规则验证
- AI 各难度行为合理性
- 残局数据完整性（200局 FEN + solution）
- 游戏状态机完整性（playing→redWon/blackWon/draw）
- 边界条件：空棋盘、满棋盘、极端走法序列

## 三、第一轮审查计划

**焦点：布局类问题**

### 检查项
1. 棋盘定位与偏移（已知 bug 验证）
2. 主界面整体布局（VStack 层级、间距、对齐）
3. 棋盘内元素定位（棋子、高亮、提示点）
4. 各弹窗/Sheet 布局（残局、回放、设置、统计、历史、主题）
5. macOS 窗口尺寸与缩放行为
6. iOS 布局适配（底部工具栏、导航栏、Sheet）
7. 暗色模式下的对比度与可读性
8. 字体渲染（STKaiti/LXGW WenKai 回退）
