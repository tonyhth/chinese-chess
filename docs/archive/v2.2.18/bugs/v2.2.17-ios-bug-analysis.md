# v2.2.17 iOS Bug 根因分析 + 修复方案

## Bug 1: 残局失败后重试无法走子 【P0】

### 根因

`PuzzleViewModel.triggerDefenderMove()` 中，AI 将死玩家或和局时提前 `return`，未重置 `isThinking = false`；同时 `resetPuzzle()` 也遗漏了 `isThinking` 的重置。

**代码位置：** `src/ChineseChess/ViewModels/PuzzleViewModel.swift`

**关键代码片段：**

```swift
// triggerDefenderMove() — MainActor.run 闭包内
// ❌ 路径1：AI 将死玩家
if MoveValidator.isCheckmate(self.playerSide, on: self.board) {
    self.gameState = .failed
    self.gameMoves[self.gameMoves.count - 1].isCheckmate = true
    return  // ← isThinking 仍为 true！
}

// ❌ 路径2：和局（自由对弈模式）
if self.puzzle.effectiveMode == .freePlay && self.checkDraw() {
    self.gameState = .draw
    return  // ← isThinking 仍为 true！
}

// ✅ 正常路径：只有走到这里才会重置
self.isThinking = false
```

```swift
// resetPuzzle() — 重试按钮调用
func resetPuzzle() {
    puzzleVersion += 1
    board = Board(fen: puzzle.initialFEN)
    isInCheck = false
    selectedPosition = nil
    legalMovesForSelected = []
    gameMoves = []
    gameState = .playing
    // ... 其他重置 ...
    // ❌ 缺少: isThinking = false
}
```

**影响链：** `resetPuzzle()` 后 `isThinking` 仍为 `true` → `handleSquareTap()` 的 `guard !isThinking` 阻止所有点击 → 用户无法走子。

### 修复方案

**方案A（推荐，防御性修复）：** 在 `resetPuzzle()` 中添加 `isThinking = false`

```swift
func resetPuzzle() {
    puzzleVersion += 1
    isThinking = false          // ← 新增
    board = Board(fen: puzzle.initialFEN)
    // ... 其余不变
}
```

**方案B（根因修复）：** 在 `triggerDefenderMove()` 的每个 early return 前加 `self.isThinking = false`

推荐 A+B 同时做：A 保证重试场景修复，B 消除源头的状态泄漏。

### 影响范围

仅影响残局模式，对弈模式（`GameViewModel`）不受影响（其 `triggerAIMove()` 在所有路径上都正确重置了 `isThinking`）。

## Bug 2: 设置页面进入后没内容 【P0】

### 根因

`SettingsView` 中 `Form` 被 `ScrollView` 包裹。iOS 上 `Form` + `.formStyle(.grouped)` 自带滚动行为，外层 `ScrollView` 导致布局冲突——`ScrollView` 提供无限纵向空间，`Form` 无法正确计算内容高度，结果内容区高度为 0，页面显示空白。

**代码位置：** `src/ChineseChess/Views/SettingsView.swift`

**关键代码片段：**

```swift
var body: some View {
    ScrollView {           // ← iOS 上多余，导致 Form 高度计算为 0
        Form {
            Section(...) { ... }
            Section(...) { ... }
            // ... 所有内容
        }
    }
    .formStyle(.grouped)  // ← Form 自带滚动，不需要外层 ScrollView
    ...
}
```

这是 SwiftUI 已知问题：`ScrollView` + `Form(.grouped)` 在 iOS 上内容不渲染。macOS 上可能碰巧能显示（macOS Form 不自动滚动），但属于未定义行为。

### 修复方案

移除 `ScrollView`，`Form` + `.formStyle(.grouped)` 在 iOS/macOS 上均自带滚动：

```swift
var body: some View {
    Form {                  // ← 直接用 Form，移除 ScrollView
        Section(...) { ... }
        Section(...) { ... }
        // ... 所有内容不变
    }
    .formStyle(.grouped)
    .navigationTitle(l10n.t("settings.title"))
    // ... 其余修饰符不变
}
```

### 影响范围

仅影响设置页面。`Form` 内容和逻辑不变，纯粹是布局修复。

## Bug 3: 历史对局选中后不显示 【P0】

### 根因

iOS 上 `GameHistoryView` 本身是 sheet 内的视图（外层 sheet 来自 `ChineseChessiOSApp`），选中对局后又通过 `.sheet` 弹出 `ReplayView`——这是 **嵌套 sheet**。iOS 上从已弹出的 sheet 内再弹 sheet 存在 SwiftUI 呈现问题：内层 sheet 可能无法正常弹出，或弹出后内容为空/立刻消失。

**代码位置：** `src/ChineseChess/Views/GameHistoryView.swift`

**关键代码片段：**

```swift
// GameHistoryView 被 app 以 sheet 呈现：
// ChineseChessiOSApp: .sheet(isPresented: $showHistory) { NavigationStack { GameHistoryView() } }

// GameHistoryView 内部又弹 sheet：
.sheet(isPresented: $showReplay) {       // ← 嵌套 sheet，iOS 上可能不工作
    if let record = replayRecord {
        #if os(iOS)
        NavigationStack {
            ReplayView(record: record)    // ← 双层 NavigationStack
                .navigationTitle(...)
                .toolbar { ... }
        }
        #else
        ReplayView(record: record)
            .frame(minWidth: 600, minHeight: 720)
        #endif
    }
}
```

**附加问题：** iOS 路径中 `ReplayView` 已有自定义标题栏（含关闭按钮），外层又套 `NavigationStack`（自带导航栏 + Done 按钮），导致双标题栏。

### 修复方案

将回放视图的呈现提升到 app 层级，避免嵌套 sheet：

**1. ChineseChessiOSApp 增加状态：**
```swift
@State private var historyReplayRecord: GameRecord?  // 已有声明但未使用
```

**2. GameHistoryView 改用回调：**
```swift
struct GameHistoryView: View {
    var onReplayRequest: ((GameRecord) -> Void)?  // 新增回调
    // 移除 @State private var showReplay / replayRecord
    // 移除 .sheet(isPresented: $showReplay) { ... }
    
    // onTapGesture 改为：
    .onTapGesture {
        onReplayRequest?(record)
    }
}
```

**3. ChineseChessiOSApp 处理回调：**
```swift
GameHistoryView()
    .toolbar { ... }
    .environment(l10n)
```

改为：
```swift
GameHistoryView(onReplayRequest: { record in
    historyReplayRecord = record
})
.toolbar { ... }

// app 层级添加 sheet/fullScreenCover
.fullScreenCover(item: $historyReplayRecord) { record in
    ReplayView(record: record)
}
```

### 影响范围

涉及 `GameHistoryView` 接口变更和 `ChineseChessiOSApp`/`ChineseChessApp` 的 sheet 管理。macOS 版本同理（改用回调 + app 层 sheet）。功能不变，仅调整 sheet 呈现层级。

## Bug 4: 中级AI思考时间太长 【P1】

### 根因

`mediumSearch` 使用固定深度 5-6 的 `rootSearch`，**无时间管理**——`TimeManager.forDifficulty(.medium)` 返回 `nil`，搜索运行到深度耗尽才返回。中局复杂局面下 depth 5 的节点数可达百万级，iOS 上可阻塞 10-30 秒。

**代码位置：** `src/ChineseChess/AI/AIEngine.swift` + `src/ChineseChess/AI/TimeManager.swift`

**关键代码片段：**

```swift
// AIEngine.swift
private func mediumSearch(for board: Board) -> Move? {
    // 开局库...
    let depth: Int
    if board.pieces.count <= 10 { depth = 6 } else { depth = 5 }
    return rootSearch(for: board, depth: depth, useTT: true, useMoveOrder: true,
                      evalConfig: .basic)  // ← 无 TimeManager，固定深度搜索到底
}

// TimeManager.swift
static func forDifficulty(_ difficulty: AIDifficulty, ...) -> TimeManager? {
    switch difficulty {
    case .beginner, .easy, .medium:
        return nil              // ← medium 无超时保护
    case .hard: ...
    case .master: ...
    }
}
```

**对比 hard/master：** 使用 `iterativeDeepeningSearch` + `TimeManager`，搜索时间可控。

### 修复方案

**核心：为 medium 引入 IDS + 时间管理，替代固定深度搜索。**

```swift
private func mediumSearch(for board: Board) -> Move? {
    // 开局库不变
    let hash = ZobristHash.hash(board: board)
    if let iccsMove = openingBook.lookupWeightedRandom(zobristHash: hash),
       let move = openingBook.parseICCSMove(iccsMove, on: board) {
        return move
    }

    // 时间限制：iOS 2s / macOS 3s
    let timeLimitMs = Self._isIOS ? 2000 : 3000
    let tm = TimeManager(timeLimitMs: timeLimitMs, startTime: Date())

    // 最大深度上限：残局 7，中局 6
    let maxDepth = board.pieces.count <= 10 ? 7 : 6

    return iterativeDeepeningSearch(
        for: board, maxDepth: maxDepth, timeManager: tm,
        searchConfig: .medium  // 使用 medium 配置
    )
}
```

**SearchConfig 新增 medium 配置：**
```swift
static let medium = SearchConfig(
    enableQuiescence: false,    // 不启用 QS，控制复杂度
    enableKillerMove: true,     // 启用杀手启发，提升剪枝效率
    enableCheckExtension: false,
    enableNullMoveFix: false
)
```

**TimeManager.forDifficulty 更新：**
```swift
case .medium:
    baseTimeMs = isIOS ? 2000 : 3000
```

### 影响范围

仅影响 medium 难度的 AI 搜索策略。棋力可能因时间截断略有下降（深度不确定），但用户体验大幅改善（思考时间从不可控变为 2-3 秒上限）。IDS 机制保证总能返回已完成的最佳深度结果。

## Bug 5: 缺少当前难度展示 【P1】

### 根因

`StatusBarView` 只显示轮次/AI 思考/将军/回合号，没有当前难度信息。iOS 底部工具栏的难度入口是 `Menu`（选择器），不显示当前选中值。用户切换难度后无任何视觉确认。

**代码位置：**
- `src/ChineseChess/Views/StatusBarView.swift` — 缺少难度显示
- `src/ChineseChess/App/ChineseChessiOSApp.swift` — Menu 不显示当前值

### 修复方案

**推荐位置：StatusBarView 的当前轮次行**

在轮次信息右侧添加难度标签，用户视线自然经过：

```swift
// StatusBarView body
HStack {
    Circle()
        .fill(viewModel.currentTurn == .red ? Color.red : Color.black)
        .frame(width: 12, height: 12)
    Text(viewModel.currentTurn == .red ? l10n.t("status.redTurn") : l10n.t("status.blackTurn"))
        .font(.subheadline.weight(.medium))

    if viewModel.isThinking { ... }
    if viewModel.isInCheck { ... }

    Spacer()

    // 新增：当前难度标签
    Text(viewModel.difficulty.displayName)
        .font(.caption2)
        .foregroundColor(.secondary)
        .padding(.horizontal, 6)
        .padding(.vertical, 2)
        .background(Color.brown.opacity(0.3))
        .cornerRadius(4)

    Text(String(format: l10n.t("status.roundN"), ...))
        .font(.subheadline)
        .foregroundColor(.secondary)
}
```

**备选/补充：iOS 底部工具栏 Menu label 显示当前难度**

```swift
// ChineseChessiOSApp toolbar
Menu {
    Button(l10n.t("difficulty.beginner")) { gameViewModel.setDifficulty(.beginner) }
    // ...
} label: {
    // 改为显示当前难度名称
    VStack(spacing: 2) {
        Image(systemName: "gauge.with.dots.needle.bottom.50percent")
        Text(gameViewModel.difficulty.displayName)
            .font(.system(size: 9))
    }
}
```

推荐 StatusBarView 方案为主（信息密度高、跨平台一致），Menu label 为辅（仅 iOS）。

### 影响范围

纯 UI 展示，不影响任何逻辑。跨平台兼容（StatusBarView iOS/macOS 共用）。

## Bug 6: 棋谱记录不工作 【P0】

### 根因

iOS 上 `RecordPanelView` 以 sheet 呈现时，`gameMoves` 作为值类型 `[GameMove]` 在 sheet 内容闭包中被捕获。SwiftUI 的 sheet 内容存在**延迟求值 + 缓存**行为：sheet 首次弹出时求值内容闭包，后续呈现视图的状态变化不一定触发 sheet 内容重新渲染。这导致棋谱 sheet 打开后始终显示首次弹出时的 `gameMoves` 快照，新走的棋不会出现在列表中。

**代码位置：** `src/ChineseChess/App/ChineseChessiOSApp.swift` + `src/ChineseChess/Views/RecordPanelView.swift`

**关键代码片段：**

```swift
// ChineseChessiOSApp — 棋谱 sheet
.sheet(isPresented: Binding(
    get: { activePanel == .record },
    set: { if !$0 { activePanel = .none } }
)) {
    NavigationStack {
        RecordPanelView(gameMoves: gameViewModel.gameMoves)
            // ↑ gameMoves 作为 let 传入，sheet 缓存后不随 gameViewModel 更新
    }
}
```

```swift
// RecordPanelView
struct RecordPanelView: View {
    let gameMoves: [GameMove]   // ← 非 @Binding，无法响应外部变化
    ...
}
```

### 修复方案

**方案：将 RecordPanelView 改为接收 GameViewModel 引用，内部直接读取 gameMoves**

```swift
struct RecordPanelView: View {
    let viewModel: GameViewModel  // ← 改为接收 ViewModel 引用
    @Environment(L10n.self) private var l10n

    var body: some View {
        VStack(alignment: .leading, spacing: 4) {
            Text(l10n.t("record.panelTitle"))
                .font(.subheadline.weight(.bold))
                .foregroundColor(.white)

            if viewModel.gameMoves.isEmpty {  // ← 直接从 viewModel 读取
                Text(l10n.t("record.empty"))
                    .font(.footnote)
                    .foregroundColor(.secondary)
            } else {
                ScrollViewReader { proxy in
                    ScrollView {
                        VStack(alignment: .leading, spacing: 2) {
                            ForEach(viewModel.gameMoves) { gm in
                                moveRow(gm)
                                    .id(gm.id)
                            }
                        }
                        .padding(.vertical, 4)
                    }
                    .onChange(of: viewModel.gameMoves.count) { _, _ in
                        if let last = viewModel.gameMoves.last {
                            withAnimation {
                                proxy.scrollTo(last.id, anchor: .bottom)
                            }
                        }
                    }
                }
            }
        }
        .padding(8)
        .background(Color(red: 40/255, green: 22/255, blue: 14/255))
        .cornerRadius(8)
    }

    // moveRow 不变
}
```

**调用方更新：**

```swift
// ChineseChessiOSApp
RecordPanelView(viewModel: gameViewModel)  // 传 viewModel

// ChineseChessApp (macOS)
RecordPanelView(viewModel: viewModel)      // 传 viewModel

// PuzzlePlayView — 需要适配
// PuzzleViewModel 不是 GameViewModel，需要保留原接口或做协议抽象
```

**PuzzlePlayView 适配方案：** 新增 `RecordPanelView` 的 `gameMoves` 重载（保留原接口），或定义 `GameMovesProvider` 协议。

简单方案——保留双接口：
```swift
struct RecordPanelView: View {
    let gameMoves: [GameMove]          // 保留给 PuzzlePlayView
    init(gameMoves: [GameMove]) { self.gameMoves = gameMoves }

    private var moves: [GameMove] { gameMoves }
    // body 中用 moves 替代 gameMoves
}

// 新增便利初始化器
extension RecordPanelView {
    init(viewModel: GameViewModel) {
        self.gameMoves = viewModel.gameMoves  // 注意：这是快照，但 viewModel 是 @Observable，sheet 内访问时 SwiftUI 会追踪
    }
}
```

更好的方案——让 `RecordPanelView` 持有 `@Observable` 对象的引用：
```swift
struct RecordPanelView: View {
    @Bindable var viewModel: GameViewModel  // @Bindable 确保 @Observable 属性被追踪

    var body: some View {
        // 直接用 viewModel.gameMoves
    }
}
```

### 影响范围

`RecordPanelView` 接口变更，需更新 `ChineseChessiOSApp`、`ChineseChessApp`、`PuzzlePlayView` 的调用方。macOS 版本同理。
