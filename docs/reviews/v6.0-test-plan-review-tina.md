#### ❌ P0：维度 2 旧值映射与设计文档 v4.2 不一致

这是本次审查发现的最严重问题。测试计划的预期结果与设计文档代码中的 `legacyMap` 有 3 处偏移：

| 旧 rawValue | 设计文档 v4.2 legacyMap | 测试计划 v1.1 预期 | 差异 |
|---|---|---|---|
| `"beginner"` | `.novice`（1级） | `.novice`（1级） | ✅ 一致 |
| `"easy"` | `.beginner`（2级） | `.amateurLow`（3级） | ❌ **偏移 +1 级** |
| `"medium"` | `.amateurLow`（3级） | `.amateurMid`（4级） | ❌ **偏移 +1 级** |
| `"hard"` | `.amateurMid`（4级） | `.amateurHigh`（5级） | ❌ **偏移 +1 级** |
| `"master"` | `.amateurHigh`（5级） | `.amateurHigh`（5级） | ✅ 一致 |

**影响**：如果按测试计划 v1.1 执行，正确的 v4.2 实现会被误判为失败。反之如果按测试计划修改实现，则用户旧存档会被悄悄升高 1 级，违反设计意图。

**根因分析**：测试计划 v1.1 的版本说明是「同步设计文档 v4.1」。设计文档从 v4.0→v4.1→v4.2 经历了多次 Skill Level 和枚举调整，测试计划的映射表可能基于 v4.0 的 5 级体系（beginner/easy/medium/hard/master 直接映射到 1-5 级）而非 v4.2 的 legacyMap。

**修复建议**：测试计划维度 2 的 2.2-2.4 必须修正为：
```
2.2  "easy"     → .beginner   (2级)
2.3  "medium"   → .amateurLow (3级)
2.4  "hard"     → .amateurMid (4级)
```
StatsManager 迁移（维度 3）的 3.2-3.4 也需要同步修正。

#### ⚠️ P1：SelfPlayRunner 混合引擎扩展实现风险

**现状**：当前 `SelfPlayRunner` 硬编码使用单一 `AIEngine`（自研引擎）。代码结构：

```swift
final class SelfPlayRunner {
    private let engine: AIEngine  // 单一引擎
    // 红黑双方都使用同一个 engine + 不同 difficulty
}
```

**需要的扩展**：`MixedEngineMatch` 模式——引擎 A（自研）执红 vs 引擎 B（Pikafish）执黑。这需要：
1. 自研引擎实现 `BestMoveProvider` 协议
2. Pikafish 也实现相同协议
3. SelfPlayRunner 改为持有两个引擎引用
4. 时限控制改为每步固定 movetime

**评估**：改动量中等（~50-80 行），但属于基础设施变更，需要额外测试本身。建议：
- SelfPlayRunner 扩展作为独立子任务，不阻塞主测试流程
- 维度 6 的交叉对弈可以在 SelfPlayRunner 扩展完成后再执行
- 如果 SelfPlayRunner 扩展延期，维度 6 可以降级为手动对弈验证

**自动/半自动分界合理性**：✅ 维度 1-4 全自动、维度 5-6 半自动的分界合理。棋力验证本质上需要人类判断或大量对弈样本，无法在单元测试框架内解决。

#### ⚠️ P1 重点说明：G2 — 未知 rawValue 处理矛盾

设计文档 v4.2 §4.1 代码：
```swift
init?(rawValue: String) {
    // 新映射... 旧值映射...
    return nil  // 未知值返回 nil
}
```

测试计划 2.6：
```
2.6  未知 rawValue → .amateurMid (4级，安全 fallback)
```

**矛盾**：`init?(rawValue:)` 返回 nil 意味着 Codable 解码会失败（throw error），而不是 fallback 到 `.amateurMid`。如果要做安全 fallback，需要在 Codable 层面做自定义捕获，或者改 init 返回 `.amateurMid` 而非 nil。

**建议**：
1. 明确设计意图——未知值是应该解码失败（暴露数据损坏），还是安全 fallback？
2. 测试计划 2.6 的预期需要与设计意图一致
3. 如果选安全 fallback，需要补充 `init(from decoder:)` 的自定义实现
